### 3.5 关键路径与砍单顺序

## 4. 确定性测试

### 4.1 平台矩阵

6 个配置：P1–P3 是原生的 x86-64 Linux（比对基准）、ARM64 macOS、x86-64 Windows；P4–P6 是 Chrome、Firefox、Safari 桌面版里的 WASM，三个浏览器跑同一个 .wasm 文件，Safari 必须是真的 Safari。机器优先用托管 CI 的免费运行器（D-064）；CI 跑不了的浏览器配置，由创始人在自己的机器上打开测试页、开着跑完，结果自动导出。构建目标、宿主和要记录的版本见[规范草案附录](./spec/lenia-q16-draft.md#det-platforms)。顺便核实三个浏览器上 WebGPU 是否默认可用（§14.7）。

### 4.2 测试协议

测试向量的定义、初始状态、步数、环面尺寸、哈希链和构建要求见[规范草案附录](./spec/lenia-q16-draft.md#det-protocol)。本计划只留三条：

1. **通过**：6 个配置上，全部测试向量的全部分段逐位相同。没有容差，没有例外。W3 之后，核与查找表在每个配置上由规范算法各自生成，哈希也逐位相同。
2. **浏览器上的时间上限**：W1 末在 P1 上实测一次大 R 向量（以及 T = 40 的向量），推算浏览器里的时间。某个向量在单个浏览器上超过 1 小时（暂定）时，浏览器上的这个向量缩短为 200 个时间单位；P1–P3 仍跑满 2000 个时间单位。
3. **出现分歧时**：找到第一个不同的分段，从那里逐步比对，直到找到原因。修好之后**全部**重跑，不只重跑出问题的配置。

### 4.3 逐位一致的前提

七条前提见[规范草案附录](./spec/lenia-q16-draft.md#det-prereq)，编号不变。日志等处引用的"计划 §4.3(n)"指附录里的同号条目。

## 5. 基准物种

### 5.1 选取标准

约 10 个（§19.1，D-045）。整个名单要覆盖下面每一项，一个物种可以同时满足几项。

| 标准 | 为什么 |
|---|---|
| 移动体（滑翔体）、旋转体、振荡体、固着体各至少 1 个 | 分别测速度和方向、角速度、周期、静止结构的长期稳定 |
| 至少 1 个多环核物种（β 至少两项） | 测多环核的生成算法 |
| ≥ 6 个柏拉图型，含 Orbium（暂定） | G2 只对柏拉图型有约束力，太少就证明不了什么。Davis（2024）没有归类的，一律算柏拉图型 |
| 至少 1 个已知的非柏拉图型物种 | 检验"允许不一致，但必须记录" |
| 至少 1 个 R 或 T 和 Orbium 不同的物种 | 证明生成算法不只对一组参数正确 |
| 大 R、大 T 测试各至少 1 个 | 精度的压力测试（第 7 节）。大 R：论文中 R 最大的物种之一，或把 Orbium 放大到 R 约 40–50（暂定）。大 T：Orbium 在 T = 40（暂定） |

## 7. 精度决策点

精度怎么定是 [D-028](./decision-log.md#d-028)：16 位精度和 v1.0 允许的 R、T 范围是同一个决定。D-028 已采纳第 7.4 节的判定方法；结果【待 D-028】：W3 末 AI 代理整理测量，W4 评审会由创始人按规则裁定，最晚在规范 v1.0 冻结之前。没定之前不做首条登记。诊断的具体做法和各方案的代价见[规范草案附录](./spec/lenia-q16-draft.md#det-precision)。

### 7.1 候选范围

规范草案 v0.1 写一个候选范围：**R 5–50，T 5–40（暂定）**。最终范围按 D-028 的四条判据定：覆盖全部基准物种；覆盖 Chan（2019）发表参数里的 R、T（W1 查出最大值；玩家重新找到文献种时要能认出）；覆盖 §8.3 离散化复跑要用的 R、T；与 D-025 的合法尺寸相容。判据要求的范围更大时，扫描和测试跟着扩大。

### 7.2 怎么诊断

W1 扫描核（R 5–60，量化误差）和查找表（T 5–40，最小的非零增量和被取整成 0 的表项比例）；W2–W3 做整数对 float64 的行为对比，含大 R、大 T 测试；没通过 G2 的柏拉图型物种，每次只量化一处（核权重、状态、查找表），分离误差来源；误差来自核权重时，W3 在原生版上试跑方案 B。

### 7.3 选项（按 D-028 的定义）

**A** 保持 16 位状态、核权重总和 2^16、u32 累加，v1.0 的 R、T 范围满足 D-028 的四条判据。**B** 提高核权重精度，用双 u32 模拟 64 位累加；附录 A 和 WGSL 精确路径要改，会变慢。**C** 保持 A，但把 v1.0 的 R、T 范围限制在 A 够用的范围内，写明哪些离散化复跑因此做不了。**D**（D-028 之外）诊断指向状态量化，A、B、C 都解决不了：要改状态位数，相当于另一份规范（如 lenia-q24），超出第 0 阶段，提交评审会。

### 7.4 判定规则（D-028 采纳的方法；阈值暂定）

- 柏拉图型基准物种（含大 R、大 T 测试）全部通过 G2，并且在判据要求的 R、T 范围内，核的 L1 误差 ≤ 1%、各环质量误差 ≤ 2%（暂定）→ **选 A**，规范写明这个范围。
- 失败来自核权重，或者核误差在这个范围内超线 → 比较 **B** 和 **C**。限制之后的范围仍能覆盖全部基准物种，做不了的离散化复跑也可以接受，就选 C；否则选 B。
- 失败来自状态量化：只在大 T 时出现，可以按 **C** 限制 T；在候选范围的低端也出现 → **D**，提交评审会，同时按第 9.4 节 G2 不通过处理。
- 失败来自查找表 → 修改查找表的生成规则（取整方式或索引精度），不需要 B。
- 选 B、C、D 中的任何一个，都要同步修订 GDD 附录 A 和 §14.2，必要时修订 §8.3。
