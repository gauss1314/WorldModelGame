## 怎么用这份日志

1. **一条决定一个条目。** 编号从 D-001 起顺序分配，永不复用，条目不删除。每个条目有固定锚点，链接写作 `[D-018](./decision-log.md#d-018)`。
2. **状态**：**提议**（有选项和建议，没拍板；建议不能当作决定）· **已采纳**（拍板人已确认，相关文档按它写）· **已否决**（保留理由，免得重复讨论）· **已替代**（写明"由 D-xxx 替代"）。
3. **拍板人**：所有条目都由创始人拍板。开发、测量和文档由 AI 代理完成（D-063），它只提建议，不拍板。
4. **改已采纳的决定**：不改原文。新增一条，写明"替代 D-xxx"和理由，原条目改为"已替代"。"提议"可以直接改。
5. **截止**：本日志是决定截止时间的唯一来源。[第 0 阶段执行计划](./phase0-plan.md)不另列截止表，只链接本日志。

6. **过了截止还没拍板**：每周五过一遍本日志。依赖它的工作可以先按建议做，标"暂定"。不可逆的动作（冻结宇宙规范、第一条登记、公开发布数据）必须等拍板。
7. **暂定数值**都标"暂定"，写明靠什么确认。GDD 修订时，在附录 D 注明条目编号。提议条目只写问题、选项、建议和理由、截止、拍板人、复审条件；技术决定的详细论证放在[宇宙规范草案](./spec/lenia-q16-draft.md)的附录。

### <a id="d-013"></a>D-013 名字与商标（§22(1)）
- 状态：已采纳（2026-10-30，做法；名称方向 W2 末按初查结果落实） · 截止：W1 初查；W2 末定对外名称方向 · 拍板人：创始人/制作人（参考法律意见；目前没有法律顾问）
- **问题**：默认名《博物志》Naturalis 与荷兰莱顿的 Naturalis Biodiversity Center 同名，又同在博物领域。

| 选项 | 好处 | 代价 |
|---|---|---|
| A 保留《博物志》Naturalis（GDD 默认） | 名字和叙事（§1、§13）契合；文档不用改 | 研究者可能误以为有关联；商标风险未知 |
| B 保留中文名，另起英文名 | 只换对外风险最大的部分 | 要重新起名并单独检索 |
| C 中英文都换 | 一次解决 | 叙事要跟着改，工作量最大 |
| D 第一阶段对外用代号，定名推迟到公开上线前 | 不用急着定名 | 代号积累不了品牌 |

- **建议**：W1 初查中国、欧盟（含比荷卢）和美国，先查尼斯分类第 9、41、42 类 [verify]，同时查域名和主要社交平台账号，并备 2–3 个候选英文名一起查。有法律意见时按意见定。W2 末仍没有法律意见，就只凭自查拍板：在第 9、41、42 类发现相同或近似的在先商标，选 B；没有发现，第一阶段继续用 "Naturalis (working title)" 或代号（D），不做品牌资产，公开上线前请律师复核。中文名《博物志》在同样的类别查到相同或近似的在先商标时，中文名也换（C），或先用代号（D）（法律备忘 §2.4）。英文候选名全部有冲突时选 D。中国实行申请在先，定名之后、第一次以该名对外公开使用之前（含面向中文社区的材料和公开仓库），就请律师复核并考虑申请（法律备忘 Q5）。定名之前，对外一律写 "Naturalis (working title)"。理由：名字会写进域名、仓库名、法律文件和招募材料，越晚改代价越大。
- **复审条件**：收到商标异议或该机构的联系；第一阶段公开上线前再查一次。

- 状态：已采纳（2026-10-30） · 截止：W4 只汇总法律与税务输入；第一阶段开放注册、开始收集数据之前定案 · 拍板人：创始人/制作人（参考法律与税务意见）

### <a id="d-018"></a>D-018 数据许可（§22(6)）
- 状态：已采纳（2026-10-30） · 截止：W1 第 1 天定方向；第一阶段首次公开导出之前定案 · 拍板人：创始人/制作人

| 选项 | 好处 | 代价 |

| A 数据 CC0，文字和图版 CC BY 4.0（GDD 默认） | 再利用没有门槛（Wikidata 也用 CC0）；署名靠共同体规范和引用 | 无法用许可强制署名 |
| B 全部 CC BY 4.0 | 署名有法律保障 | 所有数据的再利用门槛都提高；大规模合并时署名负担重 |
| A′ 在 A 的基础上，从 Chan 工作导入的条目按对方意愿用 CC BY 4.0 | 尊重原作者，不改变整本图鉴 | 混合许可；导出按条目标许可（§14.5 有 `license` 字段）；§2.2、§14.9 加"文献导入部分除外" |

- **建议**：A。A′、A″ 只在原作者授权导入时才用，按 D-062 不会发生；文献种按退路处理（D-042）。最终许可写进用户协议：玩家提交的数据按 CC0 贡献，玩家写的描述文字按 CC BY 4.0 授权；图版由运营方的生成器生成，许可人和许可形式见法律备忘 Q16。"从文献种出发找到的新种算不算 CC BY 数据的衍生物"交法律备忘。代码许可见 D-032。
- **复审条件**：法律意见认为玩家贡献按 CC0 在某些地区不可行。

### <a id="d-021"></a>D-021 哈希算法
- 状态：已采纳（2026-10-30） · 截止：W1 · 拍板人：创始人（AI 代理提建议，D-063）
- **问题**：内容寻址、承诺、轨迹指纹和核哈希用哪种哈希。写进测试向量后，只能在新版本规范里换。
- **选项**：SHA-256 / BLAKE3。
- **建议**：SHA-256，哈希串带算法前缀（如 `sha256:`），输入是规范序列化后的字节（D-026）。理由：浏览器 WebCrypto 内置，第三方最容易独立核对；一张 256×256 的状态只有 128 KiB，每 256 步才算一次，速度不是瓶颈。
- **复审条件**：SHA-256 出现可实际利用的碰撞攻击。论证见[附录](./spec/lenia-q16-draft.md#arg-d-021)。

### <a id="d-022"></a>D-022 确定性 exp 与定点数学方案
- 状态：已采纳（2026-10-30） · 截止：W1 定方向；W3 定常数和误差分析 · 拍板人：创始人（AI 代理提建议，D-063）
- **问题**：核心函数和生长函数都要算 exp，各平台的浮点 exp 结果不同；§5.4 只许用整数和定点运算。
- **选项**：A 纯定点 exp，规范写出完整算法和常数 / B 钉死某个版本的软件数学库 / C 生成阶段用 float64 基本运算自写 exp（与 §5.4 不符）。
- **建议**：A。任意精度算出的离线参考值只用来检验误差，不进规范语义。理由：第三方只看规范就能实现；计划 §4.3(1) 要求生成算法里也没有浮点。W3 同时决定量化余数的分配规则：按行优先打破平局时，单环核在 R = 5–50 的 46 个取值里有 23 个失去镜像和 90° 旋转对称，与 GDD §8.4 把镜像体、旋转体算作同一个种的规则不符。建议按规范草案 §5.4 的新提议，把到中心距离（d²）相同的格子作为一类整组分配余数，核就严格对称；规范审查在 R = 5–50、4 组 β 共 184 个核上实算过，全部对称，Σw 仍恰好是 2^16。规范草案里的状态单位 a/65535 也是新提议，随本条一起定。
- **复审条件**：定点误差在某些参数区域（如 σ 很小时）明显改变物种行为。论证见[附录](./spec/lenia-q16-draft.md#arg-d-022)。

### <a id="d-023"></a>D-023 NTT 模数与直接求和的切换
- 状态：已采纳（2026-10-30，做法；模数按 W2 实测） · 截止：W2 · 拍板人：创始人（AI 代理提建议，D-063）
- **问题**：大 R 用 NTT 时选哪个模数。两种算法算的是同一个精确整数卷积，模数和切换阈值属于参考实现，不进规范语义。
- **选项**：A 一个大于 2^32 的素数，如 2^64 − 2^32 + 1（WASM 里要模拟 128 位乘法）/ B 两个约 30 位的素数加中国剩余定理（只用 64 位运算）/ C 只用直接求和。
- **建议**：W2 按实测速度选，倾向 B；S1 的对拍也在 W2。理由：B 对 WASM 友好。D-044 选"自写"时，NTT 推到延长期或第一阶段。
- **复审条件**：实测的鉴定成本远高于 §14.3 的粗估。论证见[附录](./spec/lenia-q16-draft.md#arg-d-023)。

### <a id="d-024"></a>D-024 参数的定点编码与合法格点
- 状态：已采纳（2026-10-30） · 截止：W2 定编码草案；W3 实测后确认步长 · 拍板人：创始人（AI 代理提建议，D-063）
- **问题**：参数怎样定点编码、格点多细。§8.4(5) 用"规则点相同"判同种，规范冻结后不能再改。
- **选项**：A 十进制定点（μ、σ 存为整数 × 10^−k）/ B 二进制定点（0.15 这类文献值不能精确表示）。
- **建议**：A。μ、σ 步长暂定 0.0001；β 用分母较小的有理数；R、T 为正整数，范围由 D-028 决定。理由：Chan（2019）发表的 μ、σ 最多到小数点后 3–4 位 [verify]，0.0001 能精确表示；更细的格点会让同一个种落在更多相邻格点上，评审量变大。
- **复审条件**：W1 核对论文参数的小数位数和 β 的分母 [verify]。有落不到格点的，在 v1.0 冻结前细化编码；不得把文献参数取整到最近的格点后登记为该文献种（D-062 内部约束第 (1) 条）；冻结后仍落不到的，这个种只建 `literature_reference`（D-062）。论证见[附录](./spec/lenia-q16-draft.md#arg-d-024)。

### <a id="d-025"></a>D-025 合法环面尺寸的取值、记录位置和选取规则
- 状态：已采纳（2026-10-30） · 截止：W1 定测试用尺寸；合法尺寸集合和 D-028 的 R、T 范围一起，在 v1.0 冻结前定 · 拍板人：创始人（AI 代理提建议，D-063）
- **问题**：GDD 已定环面属于规范、鉴定尺寸由规范固定、从几种合法尺寸中选取（§5.4、§20、D-041）。还没定有哪些尺寸、记在哪里、鉴定时怎么选。
- **选项**：A 只有一个尺寸（与"几种合法尺寸"不符）/ B 一组合法尺寸，模式标本记录自己的尺寸。草稿 v0.1 的选项 C"尺寸只属于鉴定协议"与 D-012、§5.4、§20 冲突，已删去。
- **建议**：B。取 2 的幂，暂定 128、256、512；512 用于大 R，以及 256 尺寸标本的局域性和扩张复查。鉴定取能容纳成体加边距的最小合法尺寸。第 0 阶段测试向量用 256；大 R 的成体加边距放不下时才用 512（规范草案附录测试协议第 4 条）。理由：兼顾成本和大生物；扩张体在小环面上会绕回来撞上自己。
- **复审条件**：出现在最大合法尺寸里也放不下的稳定生物。论证见[附录](./spec/lenia-q16-draft.md#arg-d-025)。

### <a id="d-026"></a>D-026 状态与参数的规范序列化格式
- 状态：已采纳（2026-10-30） · 截止：W1 · 拍板人：创始人（AI 代理提建议，D-063）
- **问题**：哈希、内容寻址、分享链接和承诺都要求同一个状态、同一组参数在任何实现里得到相同的字节。
- **选项**：A 定长头加行优先、小端序的 16 位原始数据 / B 以压缩格式（如 16 位 PNG）为规范形式（结果依赖库，不能算哈希）/ C 通用格式（如 CBOR）的规范子集（容易出现两种合法编码）。
- **建议**：A 用于哈希和存档；传输时可以压缩，但哈希只对解压后的规范字节计算；参数序列化为定长整数元组。理由：简单，任何语言都能逐字节写对；W1 的哈希链要用。
- **一并决定**：卷积的求和方向（规范草案 §7.1 写作相关 Σ w·A(x+d)，是新提议）。核按 D-022 的新规则对称之后，相关和卷积结果相同，但规范仍要写死一种。
- **复审条件**：多通道 Lenia 的规范需要新格式（随新规范发，不改旧格式）。论证见[附录](./spec/lenia-q16-draft.md#arg-d-026)。

### <a id="d-027"></a>D-027 规范正文与参考实现冲突时以谁为准；出 bug 后已签发证书怎么处理
- 状态：已采纳（2026-10-30） · 截止：W2 定原则，写进规范草案；第一条登记之前定证书处理细则 · 拍板人：创始人/制作人（涉及永久性承诺）
- **问题**：§5.4 说宇宙不打补丁，§14.2(6) 说实现永久归档，但没写两者不一致时以谁为准，也没写鉴定 bug 之后已签发的证书怎么办。
- **选项**：A 正文为准，已登记条目重新鉴定，活不下来的撤回（违背"永久成立"）/ B 已归档实现为准，给正文发勘误（规范留下"怪癖"）/ C 分阶段处理。
- **建议**：C。（1）规范＝正文加随规范发布的公开测试向量；涉及 Chan 物种的内部回归向量不属于规范，不参与冲突裁决（规范草案 §9.2）。（2）冻结前，发现冲突就改错的一方。（3）冻结后的宇宙语义冲突：已归档实现的行为确定且跨平台一致，就以它为准，给正文发勘误，不理想的在新版本规范里改；行为本身不确定的不定义任何宇宙，受影响的条目按正文重新鉴定。（4）鉴定测量的 bug 不改变宇宙：修好鉴定套件，重新签发受影响的证书，旧证书标"已更正"；不再满足登记条件的走 §15 的撤回流程，编号保留，状态改为 `withdrawn`。理由：既保住永久性，也留出修正的途径。
- **复审条件**：第一次真正发生冲突之后复盘。

### <a id="d-028"></a>D-028 16 位精度与 v1.0 允许的 R、T 范围
- 状态：已采纳（2026-10-30，判定方法）；**精度部分 2026-11-04 采纳方案 B，核权重总和 W = 2^20**（创始人按建议拍板，规范草案 v0.2）；v1.0 的 R、T 范围仍在 W4 评审会定 · 截止：W4 评审会；最晚在宇宙规范 v1.0 冻结前 · 拍板人：创始人
- **问题**：16 位状态和总和为 2^16 的核权重够不够用。R 越大，每格分到的权重越小（粗算 R = 13 时最大单格权重约 300，R = 50 时约 20，近一半格子小于 5），所以精度和允许的 R、T 范围是同一个问题（§14.2、计划 §7）。早期警示：规范草案起草时用一次性脚本草算（审查时另写脚本复算过，规范草案 §10），R = 50 的单环核量化后 L1 误差约 2.4%，超过计划 §7.4 的 1% 线（暂定）。
- **选项**：A 保持 16 位状态、2^16 核权重、u32 累加 / B 提高核权重精度，双 u32 模拟 64 位累加（附录 A 和 WGSL 精确路径要改，变慢）/ C 保持 A，在 v1.0 里限制 R、T 范围。
- **判据**：本条同时决定 v1.0 允许的 R、T 范围，要（1）覆盖全部基准物种（D-045）；（2）覆盖 Chan（2019）物种的 R、T，以便它们能以 `literature_reference` 的参考标本复现（D-062，不导入） [verify：W1 从论文发表的参数中查出最大值]；（3）覆盖 §8.3 离散化复跑要用的 R、T，暂定 R 为原值的 0.5–3 倍、T 为 0.5–4 倍（§14.5 的示例是 R 10–30、T 5–40）；（4）与 D-025 的合法尺寸相容。
- **建议**：按计划 §7.4 的判定规则（暂定）实测诊断。A 在判据范围内够用就选 A；不够时比较 B 和 C。选 C 时写明哪些文献物种和哪些离散化复跑因此做不了。结论和数据一起写进本条。
- **2026-11-04 实测（测量报告 §4.2；代码仓库分支 `exp/kernel-2p20`）**：（1）A 不够用：R = 39 时整数版的航向锁到网格坐标轴上，原因只在核权重总和 2^16 的取整误差（U 的截断、生长查找表、16 位状态都不影响）。2^16 下，方向偏差在 R ≤ 18 时 ≤ 3°，R = 20、26、39 时为 16°–38°，不随 R 单调变化。判据（3）要求复跑到原值的 3 倍（R = 13 的基准要到 39），所以 C 要把基准的离散化复跑砍掉大半。（2）B 已在分支上实现：核权重总和改为 2^20，状态仍是 16 位，累加器改为 u64，U = (Σ w·A) >> 20；NTT 的数值范围 2^36 远小于两素数之积，NTT 路径不用改。R = 39 实测航向偏差约 2°（容差 5°）；3 个配置（macOS、Windows、Chromium）上公开向量和 8 个基准结构全部逐位相同，直接求和与 NTT 相同；WASM 里仍没有浮点指令。代价：NTT 不变；本机直接求和慢 1%–17%；WASM 直接求和慢约 40%（64 位乘加）；WGSL 精确路径（D-029）要用两个 u32 模拟 64 位累加，W3 再测。（3）**建议 B，核权重总和 2^20**：浏览器和基准都走 NTT，代价集中在不常用的直接求和上；R 上限可以保持 50。**2026-11-04 创始人采纳**：代码仓库主线合入，规范标识改为 `lenia-q16/0.2-draft`，公开向量和基准结构的哈希重算；G1、G2 在 v0.2 下重跑（测量报告 §4）。
- **复审条件**：研究者或悬赏需要更大的 R、T。
