## 1. 范围与原则

**本文定**：自动侦测（F10）；稳定判据；窗口裁切与尺寸；浮点状态的量化；参数怎样落在格点上；浏览器整数预检与幻影（F09）；采集承诺的时机和上传内容（F14）；探索路径的格式与隐私；离线；配额；观察记录、观察志"看见"、起点引用的判定（F27，法规第 16 条）；未描述候选的分享；防滥用；错误表。

**不在本文**：宇宙语义（规范）；承诺和事件的字节格式（数据模型 §2、§5、§6）；鉴定测量和尺寸核对（[assay v1](./assay-v1.md)）；同种判定、指纹和阈值（[dedup v1](./dedup-v1.md)）；普查算法（[普查、宇宙图与新手考察区](../data/census-atlas-novice-zone.md)，计划路径）；野外笔记的版式（[纸面生成器](../ux/paper-generator.md)，计划路径）；预览性能（[客户端性能](./client-performance.md)，计划路径）。

**原则**：

1. **浮点只用来看，整数才算数**（GDD §14.2(2)、D-029）。从量化那一刻起只用 lenia-q16 的整数语义。浮点状态和画面不上传（隐私文档原则 6）。
2. **只校验，不修正**。参数、尺寸、记录不合法就拒绝（规范 §3），不取整、不改写。文献参数尤其不取整（D-040 第 1 条、D-024、法规第 44 条第 2 款）【待 D-040、D-024】。
3. **时间以服务器为准**。客户端时间不进承诺（法规第 7 条第 1 款、GDD §14.8）。
4. **服务器不信任客户端的测量**（GDD §14.8）。影响功劳、观察志和送检的预检结果，以服务器复跑为准。
5. **出处最少**。只上传登记需要的出处（D-012）；没采集的探索留在浏览器里。
6. **红线 1**（GDD §2.2）：图鉴、物种页、图版、命名仪式、对外分享只用整数帧。浮点画面只出现在显微镜里和采集箱的"预览 / 整数"对比里（第 7 节），都标"预览"。采集箱和野外笔记里的缩略图、草图一律取整数帧（S0 或预检帧），幻影也一样。

## 2. 端到端流程

1. 玩家在显微镜里勘探，GPU 浮点预览运行（GDD §8.1）；侦测器框出"可能的候选"（第 3 节）。
2. 玩家点"采集"；系统等这个结构稳定（第 4 节）。
3. 截取一帧：裁切、隔离、选尺寸 N（第 5 节），量化成 u16 状态 **S0**（第 6 节）。**S0 就是成体快照**，也就是模式标本的候选（GDD §14.2(3) 的"量化后的成体快照"）【新提议 CH1】。
4. 立即请求采集承诺，只交哈希（第 8 节）；服务器发临时编号。
5. 浏览器用整数参考实现从 S0 跑预检（第 7 节）。通过的上传对象，服务器核对哈希并复跑；没通过的是幻影，只留承诺哈希。
6. 玩家送检（受配额限制），之后是鉴定、查重、描述、登记（数据模型 §4）。

**为什么不在整数里先跑 K 步再截一帧当模式标本**（缺口分析提的问题）：GDD 把模式标本定义为量化后的成体快照；先截后跑，承诺能在点击的那一刻做；鉴定的轨迹哈希链从 S0 开始，任何人都能复跑核对，整数宇宙里的成体就在链的头几段里。代价是 S0 带着一点量化前的痕迹：鉴定只分析后一半（assay v1 §2.5），查重的规范化取鉴定帧 `assay_frame`，不取 S0【待 dedup v1】。

```
玩家         显微镜(GPU 浮点)       侦测器           交接(WASM, Worker)          服务器(登记、日志)
 | 播种、调参   |                    |                    |                            |
 |------------>| 每个时间单位读回一次 |                    |                            |
 |             |------------------->| 跟踪，满足 C1–C5   |                            |
 |<--------------------------------- 框出"可能的候选"     |                            |
 | 点"采集"     |                    |                    |                            |
 |------------>| 等稳定（S1–S5）      |                    |                            |
 |             |---- 读回整场 binary32 位模式 ----------->| 裁切、隔离、选 N、量化 S0   |
 |             |                    |                    |-- 承诺：只有哈希 --------->| 随机数、署名标识
 |             |                    |                    |<-- prov、seq、ts ---------| collection.committed
 |             |                    |                    | 整数预检 K_p               |
 |<------------------------------------------------------ 通过 / 幻影 / 提示            |
 |             |                    |                    |-- 通过：P、S0、trail、摘要 ->| 核对哈希，复跑预检
 |             |                    |                    |<-- 最近的已知种（只读）----| precheck.done
 | 送检         |---------------------------------------------------------------->| assay.requested
```

**其他入口**：精确模式下截取的就是 u16 状态，跳过量化（第 5 节第 4 条）。工具采集从导入文件开始（第 15 节）。AI 普查在服务器上全程用整数运行，用同一版本的侦测、稳定和裁切判据，没有量化这一步，采集者写普查运行（D-008）【新提议 CH20，待普查规格】。

## 3. 自动侦测："可能的候选"（F10）

侦测器只是提示：框不框都不影响能不能采集，玩家也可以手动点选一个结构开始跟踪。侦测框不上传（第 9 节）；1 级以上 F31 的"跳过"事件怎样引用候选，由遥测与指标口径定。数值都是暂定【新提议 CH2】。

1. **采样**：模拟每走 1 个时间单位采样一次，墙钟上最多每秒 4 次；倍速高时按墙钟降频，判据仍按时间单位计。读回整场浮点状态（256² 时 256 KiB）。
2. **分割**：掩膜＝状态 > 0.1（与测量报告的形态掩膜、assay v1 的活格阈值 6554 一致：binary32 的 x > 0.1 恰好量化为 ≥ 6554）；按 ⌈R/3⌉ 格膨胀后在环面上求 8 连通分量，一个分量算一个结构，这样一个生物分开的几块会连在一起。
3. **跟踪**：相邻两次采样之间，按环面上的质心距离和质量比（0.5–2）贪心匹配；距离上限＝v_max × 两次采样相隔的时间单位 + R/2，v_max 暂定每时间单位 R/4 格，按试玩校准。匹配不上的开新轨迹。
4. **框出**：一条轨迹在最近 10 个时间单位里同时满足 C1 存在 ≥ 10 个时间单位；C2 未膨胀的掩膜面积 ≥ 0.1·πR²，外接框较长边 ≤ 512 − 4R（放得进最大的合法尺寸，第 5 节）；C3 这个分量不超过预览网格的 25%，全场掩膜不超过 50%（排除混沌区）；C4 外接框较长边在这 10 个时间单位里的最大值与最小值之比 ≤ 1.5（大小稳定，不限制长宽比）；C5 质量的最大值与最小值之比 ≤ 2。满足时框出，标"可能的候选"（英文界面 "Possible candidate"）；连续 3 个时间单位不满足就取消。
5. **周期估计**：对质量序列做自相关，得到周期估计 p̂（时间单位；找不到时为空），供第 4、7 节使用。

**目标**：**误报率 ≤ 30%**＝框出后 50 个时间单位内始终达不到第 4 节稳定判据的框 / 全部框；**漏报率 ≤ 10%**＝达到稳定判据却从没被框过的结构 / 全部这类结构。测试集（暂定 ≥ 60 段会话、≥ 100 个达到稳定判据的结构，R、T 各含范围两端）是团队在新手区和普查区的格点上播种的录制会话，用精确模式运行，可以逐位重放（浮点运行不能重放）；不在已发表物种的参数邻域取样（D-040 第 6 条、法规第 44 条第 4 款）【待 D-040】。同时上报"框出、采集后判为幻影"的比例。侦测器有版本号（如 `det/1`），写进探索路径。

## 4. 稳定判据

玩家点"采集"后，系统等结构稳定再截取（GDD §8.2）。等待期间可以变速，不能改参数或用画笔，否则重新计时。数值都是暂定【新提议 CH3】。

**判据**：窗口 W = 3·p̂，限制在 10–50 个时间单位（没有 p̂ 时取 10）。连续两个窗口同时满足：

- **S1 质量**：两个窗口的平均质量相差 ≤ 5%；
- **S2 振荡**：两个窗口的质量极差相差 ≤ 平均质量的 10%（允许振荡，只要振荡本身稳定）；
- **S3 大小**：后一窗口的最大外接框不超过前一窗口的 1.1 倍；
- **S4 形态**：以质心为中心的径向质量分布（16 档，旋转不变）在每个窗口内取时间平均，归一化后两个窗口的 L1 差 ≤ 0.1；
- **S5 邻居**（只记录，不是条件）：后一窗口里 2R 以内有没有别的结构。有也可以采，第 5 节会擦掉，探索路径记下擦掉了几个。

S1–S4 满足即在后一窗口的最后一次采样截取。最短等待 2W，即 20–100 个时间单位；按 GDD §14.7 的目标每秒 60 步估算，T = 10 时约 3–17 秒，T = 40 时最长约 67 秒（M4 实测后校准）。

**等不到稳定时**：S1–S3 连续 3 个窗口满足、只有 S4 不满足，按"形态不定"截取（混沌个体，GDD §8.3）。累计 200 个时间单位还不满足，弹出三个选择："继续等"、"现在采集"（标 `unstable`，交整数预检判断）、"放弃"。质量和外接框持续增长时提示"它在不断长大，可能是扩张体"，"现在采集"只在放得进 512 时可用。目标消失时提示"它散了"，不截取。

## 5. 窗口裁切与尺寸

**尺寸**【新提议 CH4，待 D-025、D-028】：

- **体型 e**：后一稳定窗口里，每次采样的外接框（相对本帧质心）的最大宽和最大高，取较大者。移动体的体型不因移动而变大。
- **边距 m = 2R**（暂定）。D-025 只写了"成体加边距"；assay v1 §2.2 以此为下限，核对 n ≥ D_0 + 4R（D_0 由 S0 的活格复算，不大于 e），不重新裁切。
- **N** 取合法尺寸 {128, 256, 512} 中满足 N ≥ e + 2m 的最小值（D-025 建议、规范 §4）。都不满足就不能采集（CH-E04），按 D-025 的复审条件记下。例：R = 13 时 m = 26，体型 76 格以内用 128；R = 50 时 m = 100，体型最多 312 格。

**裁切**：

1. 以截取帧外接框的中心 c 为中心，把预览环面的内容放进 N×N 全零环面的中央：输出格 (x, y) 在中央边长 min(N, N_p) 的方块内时，取预览格 ((c_x + x − ⌊N/2⌋) mod N_p, (c_y + y − ⌊N/2⌋) mod N_p)，其余为 0。N_p 是预览网格的边长（D-012：可调的只是预览网格）。
2. **隔离**：保留区＝目标的掩膜按 R 格（切比雪夫距离）膨胀。保留区外置 0；保留区内属于别的结构的掩膜格也置 0。
3. 只取一帧，不做时间平均，不做平滑。
4. **精确模式**下截取的是 u16 状态，同样裁切和隔离，跳过第 6 节的量化。

掩膜由浮点值判断，结果因设备而异。这没有关系：S0 一经承诺就固定下来，此后谁都不需要从浮点状态重算它，重算的只是它之后的一切。

## 6. 量化与参数格点

**状态量化 `q16-rne/1`**【新提议 CH5】：把每格的浮点值 x 映到规范 §4 的 u16 值 a（a 表示 a/65535）：**a = clamp(rne(x·65535), 0, 65535)**，x·65535 按 x 的精确值计算，rne 是规范 §2 的四舍六入五成双。实现不经过浮点运算，直接在 binary32 的位模式上算（读回时按 `Uint32Array` 取）：

```
q16(b):                                  # b：binary32 的 32 位模式
  s = b >> 31;  e = (b >> 23) & 0xFF;  f = b & 0x7FFFFF
  if e == 255: 拒绝采集（CH-E05）          # NaN 或 ±∞：预览出了错，不猜
  if s == 1 or e == 0: return 0          # 负数、±0、次正规数（乘 65535 后远小于 1/2）
  M = f | 2^23;  k = 150 − e             # x = M·2^−k，x·65535 = M·65535 / 2^k
  if k <= 0:  return 65535               # x ≥ 2^23
  if k >= 41: return 0                   # M·65535 < 2^40 ≤ 2^(k−1)
  return min(rne(M·65535, 2^k), 65535)   # 中间值 < 2^40，u64 够用
```

- 测试向量：1.0 → 65535；0.5 → 32768（32767.5 取偶）；2^−16 → 1；2^−17 → 0；−0.0 → 0；NaN、+∞ → 拒绝。
- 预览如果用 16 位浮点存状态，先精确转成 binary32 再量化。binary64 的来源（第 0 阶段的 float64 对照、assay v1 的文献对照）按同一个数学定义精确计算。
- 代码放在参考实现仓库里宇宙语义之外的辅助模块，编译进同一个 WASM；只用整数运算，不影响对 WASM 核心"没有浮点指令"的扫描【待 D-037】。第 0 阶段的 M6、M7 应按同一规则量化，两边的幻影率才能比较。

**参数：只在输入时选格点，采集时只校验**【新提议 CH6，待 D-024、D-028】：

- 控制台的滑块和"微调"只取 v1.0 范围内的格点（PRD F07）：μ、σ 步长 0.0001，β 是规范形式的分数，R、T 是整数。显微镜里的参数始终是规范 §3 的整数，浮点预览用 μ_q/10000 等换算值运行。
- 手动输入的十进制数落不到格点上时，输入框拒收，列出两侧最近的两个格点由玩家自己选，不替玩家取整。
- 采集时直接用这些整数生成 72 字节的参数记录（规范 §8.2），按规范 §3 逐条校验；不合法就拒绝（CH-E06）。导入和链接带来的参数记录同样只校验。
- **文献参数绝不取整来救一个种**（D-040 第 1 条、D-024、法规第 44 条第 2 款）【待 D-040】。只有参数本身落在格点上、并且有 lenia-q16 标本的文献条目（`literature`、`literature_unreproduced`）才能拖进显微镜，而且要在 G-文献可见 之后（PRD §2.3）。落不到格点的，界面写"这个文献种的参数落不到 lenia-q16 的格点上，不能在本宇宙里载入"，只提供"去附近看看"，并说明附近的结构不是这个文献种。`literature_reference` 没有数据，不能载入（D-041）。附近找到的结构按法规第 45 条人工对照【待 D-042】。
- **预览的核**【新提议 CH9】：浮点预览用参考实现按规范 §5 生成的整数核权重（w/2^16），不用连续公式，减少核量化造成的幻影（D-028 记的草算：R = 50 的单环核量化后 L1 误差约 2.4%）。生长函数仍用连续公式。M6、M7 实测时对照两种核再定。

## 7. 浏览器整数预检与幻影（F09）

**引擎**：参考实现的 WASM 构建，与服务器同一版本，在 Web Worker 里单线程运行（不用共享内存，不需要跨源隔离）【待 D-037】。R 较小、显卡支持时可以走 WebGPU 精确路径，结果逐位相同（GDD §14.2(2)）；它只算"部分符合"（规范 §9.1），可以做预检，不能做鉴定。

**步数**：K_p = 3·p̂，限制在 50–200 个时间单位（没有 p̂ 时 50）；T = 10 时为 500–2000 步。按 M6（浮点与整数的分岔步数）校准：K_p 的下限不低于从成体出发的分岔步数中位数的 3 倍（暂定）。预检不是存活测试，2000 个时间单位的存活由鉴定负责（GDD §8.3）【待 D-033】。

**判定**（只看整数状态，服务器能逐位复核，属于 D-034 所说必须逐位可复现的一类【待 D-034】；数值暂定）【新提议 CH8】：

| 结果 | 条件 | 处理 |
|---|---|---|
| 死亡 | 任一时刻总质量 < S0 的 5%，或所有格子 < 6554（即 0.1） | `phantom`。精确模式下改称"裁切后不能存活" |
| 散了 | 结束时没有任何一个结构（第 3 节的分割）的面积 ≥ 0.1·πR² | 同上 |
| 分开 | 结束时有 ≥ 2 个面积 ≥ 0.1·πR² 的结构 | `ok`，提示 `split`："分成了几个，可能是复制体或辐射体"；类别由鉴定判。不能当幻影拦下，否则复制体、辐射体（GDD §8.3）永远进不了图鉴 |
| 撑满 | 外接框达到 N − m，或质量持续增长 | `ok`，提示 `expanding`："可能是扩张体，或窗口太小"；局域性以 assay v1 §3.2 为准 |
| 通过 | 以上都不是 | `ok` |

两种只在客户端算的提示，服务器没有浮点数据，不复核：`morphed`＝预检最后 10 个时间单位的径向分布与浮点稳定窗口的 L1 差 > 0.2，采集箱并排播放"预览里的样子（标'预览'）/ 整数宇宙里的样子"，玩家确认后客户端才放开送检按钮，之后一切展示都用整数帧；`unstable`＝第 4 节"现在采集"截取的。数据模型的 `precheck` 只有 ok / phantom，这些提示放进新字段 `precheck_notes`（split / expanding / morphed / unstable），复跑方记在 `precheck_by`（client 只用于客户端报的幻影，见下；其余为 server）。

**幻影**【待 D-029】：

- 采集箱里标"只在浮点预览中出现"（英文界面 "Seen only in the float preview"），一句话说明：预览为了速度用近似计算，在本宇宙的精确规则 lenia-q16 里它活不下去，所以它不是物种；裁切时擦掉了它依赖的邻居也会这样。两个按钮："在这里用精确模式重新播种"、"删除"。
- 不能送检、不能描述、不进观察志、不能分享成标本（PRD F09）。状态记录和探索路径不上传，服务器只有承诺哈希和 `precheck.done`（phantom，`precheck_by: client`）。客户端报的幻影只影响报告者自己，服务器照记、不复核。
- 采集箱和野外笔记里的图取 S0（量化后的整数帧），保持灰色和"只在浮点预览中出现"的标注，不配编号和名字，导出也一样。

**服务器复跑**：预检通过的上传后，服务器用原生构建按同一 K_p 复跑，结果写进 `precheck.done`。客户端同时上传预检摘要（`precheck/1`：K_p、每 256 步的哈希链点、结果）。两者应逐位一致；不一致说明客户端构建或平台有确定性问题，以服务器为准，按规范 §9.3 定位，该构建暂停接受客户端预检（CH-E16）。每次采集因此顺带做一次跨平台对拍。

**设备太慢**：按 M5 估算预检要超过 3 分钟（暂定，如 512²、R = 50）时，跳过本地预检，先承诺、再上传，由服务器预检。这时状态在预检前上传；判为幻影的，服务器写完 `precheck.done` 就删掉上传的对象，只留承诺哈希（数据模型 N11 只管描述和鉴定没通过的送检，不管幻影）【新提议 CH8】。

**幻影率**【新提议 CH19】：只从采集记录的 `precheck` 汇总，不另设遥测（隐私文档原则 6），两种口径都进看板（F38）。(1) **预检幻影率**＝浮点模式下判为幻影的 / 浮点模式的全部采集记录。(2) **M7 口径**：每周从浮点模式、预检通过的记录里抽 10%（暂定，每周最多 200 件），由服务器跑满 2000 个时间单位，得到其中的死亡比例 q，幻影率 ≈ p1 + (1 − p1)·q，p1 是 (1)。超过 20%（M7 警戒线，暂定）时按 D-029 的复审条件考虑改默认。

## 8. 采集承诺与上传

**时机**：S0 和探索路径定下来的那一刻（预检之前）就请求承诺；离线时在恢复后请求（第 10 节）。承诺时间是服务器写日志的时间。

**两步上传**【新提议 CH7】：

| 步骤 | 客户端发 | 服务器做 | 日志 |
|---|---|---|---|
| 1 承诺 | `upload_id`（128 位随机数，用于幂等）；规范标识；参数记录哈希 hP；N；状态记录哈希 S；探索路径哈希；`method`；是否经链接（第 14 节） | 生成随机数和署名标识，按数据模型 §5 算采集承诺，发临时编号 | `collection.committed`，只公开承诺哈希 |
| 2 上传（预检通过后） | 参数记录、状态记录（传输时压缩，哈希按解压后的规范字节【待 D-026】）、探索路径对象（含起点段对象，第 9 节）、预检摘要 | 重算 hP、S 和路径哈希，必须与承诺一致（CH-E11）；校验参数和尺寸；复跑预检；算 `near_literature`（私，法规第 45 条【待 D-042】）；用公开索引给出最近的已知种（只读，不写查重报告）【待 dedup v1】 | `precheck.done` |
| 幻影 | 只发预检结果 | 记 phantom | `precheck.done` |

- 承诺的内容与法规第 9 条、数据模型 §5 一致，本文不加字段。核与查找表的哈希由服务器从参数重算，不上传。浮点状态、浮点画面和侦测结果都不上传。
- 状态记录 256² 是 128 KiB，512² 是 512 KiB（规范 §8.4）。预检通过、却没送检的标本也会上传（采集者功劳要比较的是"上传了快照并通过预检"的记录，法规第 7 条第 3 款），[团队预算](../product/team-budget-funding.md) §3.3 只按送检数算了存储，这部分要补进去（见文末）。
- "最近的已知种"只比对已登记条目和公开的待描述库（D-008），不比对别人的私密采集和审核中的描述，也不显示是否靠近文献种：那个标记是私密的，到描述时才按法规第 45 条第 2 款说明。
- 只有服务器预检 `ok` 的才能送检（`assay.requested`，第 11 节的配额）。鉴定可以把 S0 放进更大的尺寸跑（D-025，assay v1）。

## 9. 探索路径与隐私

数据模型 §3.2 定了 `seed`、`steps`、`from`，其余在这里定【新提议 CH10】：

```
{"fmt": "trail/1", "spec": "lenia-q16/1.0", "step_unit": 1000,   # 步数一律按 1,000 步取整（rne）【待 D-039】
 "seed": {"kind": "soup",                     # soup / brush / catalog / link / import；gen（噪声、CPPN）保留，PRD 第 4 节推迟
          "gen": "soup/1", "rand": "<32 位十六进制>", "size": [64, 64], "density_q": 5000, "sym": "none",
          "n0": 256, "state0": "sha256:…"},   # 汤由整数生成器产生，可以逐位重现（GDD §14.2(3) 的"原始的汤"）
 "start": "sha256:…",                         # 播种时参数记录的哈希
 "steps": [[1000, "param", "mu_q", 2121], [2000, "mode", "exact"], [2000, "brush", "sha256:…"]],
 "from": "sha256:…",                          # 起点段对象的哈希，只在从某个种出发时出现（第 13 节）
 "capture": {"k": 3000, "mode": "float", "n": 128, "c": [201, 77], "m": 26, "erased": 1, "stable": "ok",
             "detector": "det/1", "quant": "q16-rne/1", "kernel": "spec", "grid": 256}}

{"fmt": "origin-segment/1", "len": "LEN-001876",   # 起点段：X 的标本和模式产地，之后的操作只记顺序，不记步数
 "state": "sha256:…", "params": "sha256:…", "ops": [["param", "sigma_q", 312], ["reseed"]]}
```

- **步数 k**：从本次播种起的模拟步数，按 `step_unit` 取整（隐私文档 PC2：路径登记时公开，精确步数会公开每一步停留多久，0 级不收这类数据，1 级只许用于推荐）。回放到早先的某一步再继续，记 `["rewind", k]`，之后从那一步接着数。同一档里的几个操作按数组顺序。
- **操作**：`param`（字段、新的整数值）、`rewind`、`brush`（笔画列表的哈希，列表随路径一起保存）、`place`（拖入一个条目的标本、位置、90° 旋转和镜像）、`mode`（float / exact）、`grid`（改预览网格）。**不记**：暂停、变速、放大、宇宙图上的浏览、侦测框、墙钟时间（数据模型 N9）。
- **汤**：`soup/1` 建议用 assay v1 的 SHA-256 计数器模式生成器（AS10），由 `rand` 播种【待 assay v1】。
- **出处的范围**：从最后一次播种到采集（D-012 的"从播种到采集"）。起点段单独成一个对象，路径里只有它的哈希：没成为新种的可以删掉对象，而承诺里的路径哈希照样成立（第 13 节）。
- **浏览器本地**：当前会话的操作只在内存里，用来在采集时组装路径；"继续上次考察"在本地保留 24 小时（暂定）。没有采集就不上传，也不在服务器留任何记录。

| 数据 | 归类 | 0 级 | 1 级以上 |
|---|---|---|---|
| 采到的标本的路径（seed、steps、capture） | 出处（D-012） | 预检通过后上传，登记时公开 | 同左 |
| 步数精度 | — | 取整到 1,000 步（暂定，隐私文档 PC2）【待 D-039】 | 同左 |
| 起点段对象 | 出处，只在采到新种时保留【待 D-039】 | 随路径上传；没成为新种的删除（第 13 节） | 同左 |
| 幻影的路径 | — | 不上传，只有承诺里的哈希 | 同左 |
| 没采集的探索：参数路径、停留、跳过、放大、侦测框 | 好奇心数据 | 不离开浏览器 | 第一阶段只按 F31 记"有趣"、跳过、停留、放大，不记参数路径 |
| 观察记录（第 12 节） | 描述的要件 | 本人按"记一笔观察"才生成，存在浏览器里，提交描述时才上传（隐私文档 §3.3） | 同左 |
| 观察志条目（第 12 节） | 游戏功能（隐私文档 PC3），不是出处也不是好奇心数据 | 私库，只给本人看，不进日志和导出（只给计数） | 同左 |

- 步数取整之后，所有标本都做不了"出生可复现"（PRD 第 4 节已推迟），交 D-039 一并权衡。
- 未成年人：D-031 建议 alpha 只对 18 岁及以上开放。改为允许未成年人时，默认连出处路径也不收集（GDD §11.2"未成年人默认不收集轨迹数据"，研究简介已对外这样写，只能加强）；他们的采集怎样承诺、能否登记，随隐私文档 PC13 定 [待法务确认]。2 级在伦理审批前不提供（D-036）。

## 10. 离线与网络不稳

数值都是暂定【新提议 CH11】。

```
玩家          浏览器（采集箱，IndexedDB）                        服务器
 | 采集（离线） |                                                   |
 |------------>| S0、路径定稿；本地预检；状态"待承诺"                 |
 |             |   ……网络恢复……                                    |
 |             |-- 承诺（upload_id，按截取顺序）------------------->| collection.committed
 |             |<-- prov、seq、ts：采集时间以此为准 ------------------|
 |             |-- 上传对象和预检摘要（失败按退避重试，同一 upload_id）->| 核对哈希，复跑预检
 |             |<-- precheck.done、最近的已知种 ---------------------|
 |<------------| "3 件离线采集已承诺，采集时间按上传时刻"              |
```

- **离线能做**：勘探、侦测、截取、量化、本地预检、观看预检的整数动画。**不能做**：承诺、送检、最近的已知种、记观察记录（要服务器签发的凭据，第 12 节）、复现分享。
- **队列**：最多 50 件或 100 MB（暂定），满了先提示删除。浏览器存储被清除或无痕窗口关闭时队列会丢，截取时就提示。承诺之前删掉的截取，服务器从不知道。
- **幂等**：重试带同一个 `upload_id`；同一账户的同一 `upload_id` 只写一次，重复请求返回原来的临时编号（`upload_id` 保留 7 天，暂定）。步骤 1 不到 1 KiB，先保证它成功；步骤 2 失败不影响承诺。
- **时间**：离线截取只在本地显示"截取于（本机时间）"，并说明采集时间以上传时刻为准；本机时间不上传。
- **版本**：客户端构建不在服务器的允许列表里（如修过确定性 bug）时，先更新再上传。S0 和参数记录与引擎版本无关，更新后照常承诺，预检重跑。
- **受限模式**（PRD 第 5 节）："只勘探"时"采集"按钮不可用，截取不能进入采集箱；"不开放描述"时采集和送检照常。

## 12. 观察记录、观察志与描述要件

**观察记录**（法规第 16 条的判定口径；字段见数据模型 §3.5）【新提议 CH14】：

| 项 | 规定（数值暂定） |
|---|---|
| 对象 | `target`：描述用时是临时编号，记观察志时是 LEN |
| 载入 | 自己的标本从采集箱载入；待描述库的普查标本、别人确认分享的标本和已登记条目按状态哈希从内容存储载入（数据模型 §7）。在它自己的规则点和 N 上运行。载入后改过参数、用过画笔、拖入过别的东西，这次就不算 |
| 最短 | 模拟 ≥ max(20 个时间单位, 2 个周期)，墙钟 ≥ 30 秒并且页面可见 |
| 动作 | 本人按"记一笔观察"才生成；被动停留不生成 |
| 方式 | `exact`：整数精确运行，带挑战校验；`float`：浮点预览，不校验，物种页如实显示方式 |
| 凭据与时间 | 按"记一笔观察"时向服务器要一张无状态签名的凭据 {target, mode, issued_at, r（只在 exact）, 随机数}，服务器不保存；`at` 取 issued_at；`duration_s` 由客户端报；公开时粗化到日和分钟（数据模型 N10） |
| 存放与上传 | 记录连同凭据存在浏览器里，提交描述时随描述上传；服务器验签、核对挑战、分配 `obs:` 编号，再算描述提交承诺（隐私文档 §3.3："只在提交描述时上传"）。浏览器存储被清掉就要重新观察 |
| 采集时 | 等稳定时看过的这一段满足最短要求的，承诺时可以勾选记为一条 `float` 观察（默认不勾），`at` 取承诺的服务器时间。预检带 `morphed` 的不能这样记：整数宇宙里的样子与看过的不同 |

**挑战校验**：精确模式载入后，Worker 在本机算出第 257–511 步每一步状态记录的哈希；凭据里的 r 在这个范围里随机，客户端当即给出第 r 步的哈希，记进本地记录。服务器上传时核对：鉴定时顺带私存这件标本第 257–511 步每步的状态哈希（约 8 KiB），直接比对，没存的现跑 r 步【待 assay v1】。不用证书里的哈希链点，是因为登记后它们就公开了（数据模型 §3.2 的分段列表）。核对不上：拒收这条记录，按确定性问题告警（CH-E21）。数据模型的观察记录要加字段 `check`（challenge / none）。挑战只证明本机确实精确运行过这件标本，证明不了看了多久；伪造观察记录按法规第 56 条之一处理。

**有效描述的要件**（法规第 14 条第 5 款）：至少一条描述者本人对**所描述的这件标本**的观察记录，随描述上传，编号写进描述提交承诺（数据模型 §5）。描述 AI 普查标本、别人分享的标本时，描述者必须自己载入观察；描述自己采集的，采集时那条 `float` 记录（不带 `morphed`）就够。

```
描述者          浏览器                                         服务器
 | 打开待描述库里的标本 |                                         |
 |-------------->| 按状态哈希载入，精确模式；Worker 算好第 257–511 步的哈希 |
 | 看 ≥ 20 时间单位、≥ 30 秒                                         |
 | "记一笔观察"   |-- 要凭据（target、mode）----------------------->| 签名 {issued_at, r}，不保存
 |               |<-- 凭据；本机记下第 r 步的哈希、duration_s --------|
 | 写诊断、提交   |-- 描述 + 观察记录 ------------------------------>| 验签、核对、分配 obs:…
 |               |                                                 | description.submitted
```

**观察志"看见"**（GDD §8.7，F27）【新提议 CH13】：两条路径，对应数据模型观察志条目的 `via`：

| via | 条件 | 说明 |
|---|---|---|
| `collected` | 本人的采集记录；服务器复跑预检 `ok`；认定是 LEN-X：鉴定后查重判同（`auto_same`）或评审判同，或者**轻量识别**：采集点与 X 的模式产地或参考标本是同一规则点，且服务器预检得到的指纹在 dedup v1 的自动判同阈值内【待 dedup v1】 | 轻量识别只读，不写查重报告，不决定任何名称和功劳。识别不出的显示"可能是 LEN-X（未确认）"，不计；玩家可以送检 |
| `exact` | 从图鉴拖入、打开链接或从物种页载入 X 的模式标本或参考标本，精确模式运行，满足观察记录的最短要求，本人按"采集到观察志"；凭据和挑战同上，服务器当场核对 | 不产生采集承诺：标本已经在图鉴里。只写观察志条目，不上传观察记录。GDD §8.7 的"采集到"在这条路径上解释为这个明确的记录动作，待创始人确认 |

- 不算"看见"：幻影（预检不通过，F09）；只在浮点预览里看过；`literature_reference`（没有标本，只能经 `collected` 路径按法规第 45 条认定为再发现后记入【待 D-042】）。
- 还没登记的种：登记生效时补进观察志，`first_seen` 取本人那条采集记录的日期。
- 教程里"亲眼看见 Orbium"（GDD §7）走 `exact` 路径；没有许可或 G-文献可见 未满足时按退路模式，不出现文献种（PRD F13）。

## 13. 起点引用（"从这里出发"）

从物种页"从这里出发"，或把一个条目的标本拖进显微镜，都在本机开一个起点段（第 9 节的 `origin-segment/1`），采集时它的哈希写进路径的 `from`（数据模型 §3.2）。由此采到的标本后来登记为新种时，起点得到一次起点引用（GDD §3.3(5)、§9.4）。成立条件（数值暂定）【新提议 CH15】：

| # | 条件 | 怎么核对 |
|---|---|---|
| O1 | 起点 X 是 `valid`，或有标本的文献条目；起点段的初始状态是 X 的模式标本或参考标本，参数是 X 的模式产地 | 服务器查 X 的记录 |
| O2 | 不断链：宇宙图跳转、打开链接、载入别的标本、超过 24 小时的会话中断都会清掉本机的起点段；拖入另一个种时，起点改成那个种（一件标本只有一个起点，后来的替换先前的） | 客户端在断链时清掉；服务器检查起点段里没有断链操作 |
| O3 | 邻近：采集点与 X 的模式产地核函数族、生长函数族、β 都相同，\|Δμ_q\| ≤ 300、\|Δσ_q\| ≤ 60（即 ±0.03、±0.006）；R、T 可以不同 | 从参数记录算 |
| O4 | 参数链连续：从 X 的参数出发，依次应用起点段和本段的 `param` 操作，正好得到采集时的参数 | 只重放参数操作，不重放模拟 |
| O5 | 新种 Y 以这件标本为模式标本登记生效，查重判为与 X 不同的种 | 登记事件 |
| O6 | Y 只按自己模式标本的路径记一次起点引用；同一对 (Y, X) 只记一次 | — |
| O7 | 自引用：Y 的采集者或描述者与 X 的采集者或描述者是同一账户时，记 `self: true`，不计入物种页的引用数（§9.4） | 私库比对账户 |

- 记录：Y 登记生效时核对 O1–O7，写 `citation.recorded`（kind origin，`evidence` 是起点段对象的哈希，`self` 按 O7）。起点段对象随 Y 的出处公开。D-039 建议"只保留最终采到新种的那段"【待 D-039】：采集记录被玩家删除、鉴定没通过或查重判为已知种时，服务器删掉起点段对象（幻影的根本不上传）；路径对象里只有它的哈希，承诺照样能核对。其余的随采集记录保留到上述情况发生或账户删除。
- **局限**：浮点模拟不能重放，服务器只能核对操作序列的一致性。伪造路径最多给别人的种加一次引用；第一阶段不算声望（PRD 第 4 节），引用图分析留到第二阶段（§9.4）。不另设服务器签发的"起点票据"：它证明不了路径真实，还会在服务器上留下玩家从哪个种出发的行为记录。"从这里出发"不通知服务器。

## 14. 分享未描述的候选

D-015 的建议要求分享野外笔记时隐藏未描述候选的参数；法规第 11 条允许分享未描述标本的链接，但要先提示【待 D-015】。本文把两者合成下面两种分享方式【新提议 CH16】：

| 方式 | 内容 | 什么时候用 |
|---|---|---|
| **观看分享** | 用整数预检帧渲染的短片或图片、临时编号、承诺哈希、"未描述"字样。不含参数、尺寸、状态和规则点 | 采集箱"分享"的默认；野外笔记里的未描述候选 |
| **复现链接** | 数据模型 §7 的 `/s/1#p=…&n=…&h=…&z=…`，参数和状态都在里面 | 玩家确认提示之后 |

- **提示**（法规第 11 条第 2 款）："拿到这个链接的人都能复现、采集并描述它。命名权归第一个有效描述者；你的采集者功劳不变。"英文界面："Anyone with this link can reproduce, collect and describe it. The name goes to the first valid description; your collector credit stays."
- 确认之后，服务器才允许凭哈希取这件标本的状态记录（数据模型 §7 的例外）。"已分享"只记在私库，不进日志。
- **野外笔记**（F37）：未描述候选不写参数、R、T、β，图上没有坐标；路线在离候选一格粗网格（暂定 Δμ 0.01、Δσ 0.003）处截止，最后一段不画；草图取整数帧。分享出去的文件里查不到参数（F37 的验收）。
- **链接来源**【新提议 CH17】：打开一个未描述标本的复现链接后，同一浏览器会话里在同一规则点采到的东西都标 `link_source`（法规第 11 条第 3 款），不算新的"第一次采集"；从链接直接播种的，`seed.kind` 为 link。
- 幻影不能分享成标本；观看分享也不提供（第 7 节）。
- 登记后是普通的条目链接。待描述库里的普查标本本来就公开（D-008），复现链接不需要确认，但同样提示任何人都可以描述。

## 15. 防滥用与工具采集

- **手动与工具**（法规第 19 条）：人在显微镜里点"采集"得到的是手动采集，用了侦测器和好奇心罗盘也算。导入的文件一律是工具采集；用自己的脚本驱动界面采集的，打开"这次用了自己的脚本或程序"开关。采集方式写在 `collection.committed` 的载荷里，进链之后改不了（数据模型 §5）；标错按法规第 56 条之一处理。工具采集不算人类发现【待 D-043】。
- **导入**【新提议 CH18】：接受参数记录和状态记录（规范 §8 的二进制，导出包里的 `.parm`、`.stat` 文件），只校验不修正；N 必须合法，分割后必须恰好一个结构，并且 N ≥ D_0 + 4R（同 assay v1 §2.2，否则鉴定会拒）（CH-E17）；不裁切，直接作为 S0 预检；`seed.kind` 为 import，记文件哈希。第一阶段不开放采集和描述的接口（PRD 第 4 节；法规第 19 条第 3 款）。
- **只用服务器端信号**：只用隐私文档第 25 项列的三种：同一网络的多个账户、配额用满、采集接近每日上限（保留 30 天）【待 D-039】[待法务确认]；网络标识只取服务器日志里的 IP，不做设备指纹（隐私文档 PC4）。不在客户端采集鼠标轨迹、按键节奏一类的行为特征【新提议 CH18】。
- **刷采集者功劳**：只有上传了快照、服务器预检通过的记录参加比较（法规第 7 条第 3 款）；每日上限；经链接得到的不算（第 14 节）。
- **伪造预检、伪造观察**：服务器复跑预检（第 7 节）；精确观察有挑战校验（第 12 节）。
- **刷起点引用**：第 13 节 O2–O7。
