## 怎么用这份日志

1. **一条决定一个条目。** 编号从 D-001 起顺序分配，永不复用，条目不删除。每个条目有固定锚点，链接写作 `[D-018](./decision-log.md#d-018)`。
2. **状态**：**提议**（有选项和建议，没拍板；建议不能当作决定）· **已采纳**（拍板人已确认，相关文档按它写）· **已否决**（保留理由，免得重复讨论）· **已替代**（写明"由 D-xxx 替代"）。
3. **拍板人**写角色（GDD §19.2）。目前只有创始人，所有条目实际都由创始人拍板。技术条目写"创始人（暂代后端/图形；到岗后可提修改）"：工程师到岗后，可以对仍在"提议"的条目提修改。顾问只提意见，不拍板。
4. **改已采纳的决定**：不改原文。新增一条，写明"替代 D-xxx"和理由，原条目改为"已替代"。"提议"可以直接改。
5. **截止**：本日志是决定截止时间的唯一来源。[第 0 阶段执行计划](./phase0-plan.md)不另列截止表，只链接下面的索引。各周要拍板的事：

   | 周 | 要拍板的决定 |
   |---|---|
   | W1 | 第 1 天：许可方向 D-018、单人时 B 线做法 D-044、命名权归属 D-015（尽量）；第 2 天（第 3 天发信前）：对外承诺 D-040；W1 内：哈希与序列化 D-021、D-026，定点数学方向 D-022，测试用环面尺寸 D-025，代码许可 D-032，工具链最小集 D-037，继续标准的解释 D-046，商标初查 D-013；W1 末：基准物种名单 D-045 |
   | W2 | 对外名称方向 D-013（W2 末）；参数编码草案 D-024；NTT 模数 D-023；规范冲突原则 D-027；伦理审查路径 D-036；D-015 最晚在命名法规 v0 动笔前 |
   | W3 | 精度建议 D-028（W3 末由后端提出）；格点步长 D-024；暂定数值 D-033；定点常数 D-022；学名形式 D-017；提交伦理审查申请 D-036 |
   | W4 | 评审会拍板：精度与 v1.0 允许的 R、T 范围 D-028，第一阶段时长 D-020，文献退路细则 D-042，进入、延长、暂停或调整方向；同时定 D-031、D-034（方向）、D-032（公开时间）；D-014、D-029 只汇总输入 |

6. **过了截止还没拍板**：每周五过一遍本日志。依赖它的工作可以先按建议做，标"暂定"。对外发出的文字和不可逆的动作（发出许可请求和简介、冻结宇宙规范、第一条登记、公开发布数据）必须等拍板。没拍板的规则，对外一律写成提议（"proposed"）。
7. **暂定数值**都标"暂定"，写明靠什么确认。GDD 修订时，在附录 D 注明条目编号。提议条目只写问题、选项、建议和理由、截止、拍板人、复审条件；技术决定的详细论证放在[宇宙规范草案](./spec/lenia-q16-draft.md)的附录。

### <a id="d-013"></a>D-013 名字与商标（§22(1)）
- 状态：提议 · 截止：W1 初查；W2 末定对外名称方向 · 拍板人：创始人/制作人（参考法律意见；目前没有法律顾问）
- **问题**：默认名《博物志》Naturalis 与荷兰莱顿的 Naturalis Biodiversity Center 同名，又同在博物领域。

| 选项 | 好处 | 代价 |
|---|---|---|
| A 保留《博物志》Naturalis（GDD 默认） | 名字和叙事（§1、§13）契合；文档不用改 | 研究者可能误以为有关联；商标风险未知 |
| B 保留中文名，另起英文名 | 只换对外风险最大的部分 | 要重新起名并单独检索 |

- **复审条件**：收到商标异议或该机构的联系；第一阶段公开上线前再查一次。

### <a id="d-018"></a>D-018 数据许可（§22(6)）
- 状态：提议 · 截止：W1 第 1 天定方向（第 3 天发出许可请求）；第一阶段首次公开导出之前定案 · 拍板人：创始人/制作人
- **问题**：§14.9 建议图鉴数据用 CC0，描述文字和图版用 CC BY 4.0，§22(6) 还没定。许可请求函第 2 节要写进"当前方案"和对方不同意时的做法。Chan 的代码是 MIT 许可，但物种数据能否以 CC0 再发布不确定。按我们的理解，数据一旦以 CC0 或 CC BY 发布，许可不能收回 [待法务确认]。

| 选项 | 好处 | 代价 |
|---|---|---|
| A 数据 CC0，文字和图版 CC BY 4.0（GDD 默认） | 再利用没有门槛（Wikidata 也用 CC0）；署名靠共同体规范和引用 | 无法用许可强制署名 |
| B 全部 CC BY 4.0 | 署名有法律保障 | 所有数据的再利用门槛都提高；大规模合并时署名负担重 |
| A′ 在 A 的基础上，从 Chan 工作导入的条目按对方意愿用 CC BY 4.0 | 尊重原作者，不改变整本图鉴 | 混合许可；导出按条目标许可（§14.5 有 `license` 字段）；§2.2、§14.9 加"文献导入部分除外" |
| A″ 对方要求数据按 MIT 处理 | 尊重对方的原许可 | 导入条目标 MIT，附 Chan 的版权声明和 MIT 全文，导出时一并附上；混合许可；MIT 用在数据上是否合适，交法律备忘 |

- **建议**：A 作为"当前方案"写进许可请求，写成提议。对方更希望 CC BY 就用 A′，要求按 MIT 就用 A″。对方说"代码是 MIT，随便用"时，只视为同意导入，(b) 仍要书面确认一次（许可请求函第 5 节）。不导入时按退路处理（D-042）。理由：对方的偏好只约束来自对方的数据，不必改变整本图鉴。最终许可写进用户协议：玩家提交的数据按 CC0 贡献，玩家写的描述文字按 CC BY 4.0 授权；图版由运营方的生成器生成，许可人和许可形式见法律备忘 Q16。致 Chan 的确认句由 Chan 以权利人身份作出放弃或许可（法律备忘 §4.2）。"从文献种出发找到的新种算不算 CC BY 数据的衍生物"交法律备忘。代码许可见 D-032。
- **复审条件**：收到 Chan 的答复；法律意见认为玩家贡献按 CC0 在某些地区不可行。

### <a id="d-021"></a>D-021 哈希算法
- 状态：提议 · 截止：W1 · 拍板人：创始人（暂代后端/图形；到岗后可提修改）
- **问题**：内容寻址、承诺、轨迹指纹和核哈希用哪种哈希。写进测试向量后，只能在新版本规范里换。
- **选项**：SHA-256 / BLAKE3。
- **建议**：SHA-256，哈希串带算法前缀（如 `sha256:`），输入是规范序列化后的字节（D-026）。理由：浏览器 WebCrypto 内置，第三方最容易独立核对；一张 256×256 的状态只有 128 KiB，每 256 步才算一次，速度不是瓶颈。
- **复审条件**：SHA-256 出现可实际利用的碰撞攻击。论证见[附录](./spec/lenia-q16-draft.md#arg-d-021)。

### <a id="d-022"></a>D-022 确定性 exp 与定点数学方案
- 状态：提议 · 截止：W1 定方向；W3 定常数和误差分析 · 拍板人：创始人（暂代后端/图形；到岗后可提修改）
- **问题**：核心函数和生长函数都要算 exp，各平台的浮点 exp 结果不同；§5.4 只许用整数和定点运算。
- **选项**：A 纯定点 exp，规范写出完整算法和常数 / B 钉死某个版本的软件数学库 / C 生成阶段用 float64 基本运算自写 exp（与 §5.4 不符）。
- **建议**：A。任意精度算出的离线参考值只用来检验误差，不进规范语义。理由：第三方只看规范就能实现；计划 §4.3(1) 要求生成算法里也没有浮点。W3 同时决定量化余数怎样分配才能让核保持旋转和镜像对称（例如按对称轨道分配余数）：按行优先打破平局时，核在某些 R 下不严格对称（规范草案的草算：R = 50 时有 12 个格子不对称），与 GDD §8.4 把镜像体算作同一个种的规则不符。
- **复审条件**：定点误差在某些参数区域（如 σ 很小时）明显改变物种行为。论证见[附录](./spec/lenia-q16-draft.md#arg-d-022)。

### <a id="d-023"></a>D-023 NTT 模数与直接求和的切换
- 状态：提议 · 截止：W2 · 拍板人：创始人（暂代后端/图形；到岗后可提修改）
- **问题**：大 R 用 NTT 时选哪个模数。两种算法算的是同一个精确整数卷积，模数和切换阈值属于参考实现，不进规范语义。
- **选项**：A 一个大于 2^32 的素数，如 2^64 − 2^32 + 1（WASM 里要模拟 128 位乘法）/ B 两个约 30 位的素数加中国剩余定理（只用 64 位运算）/ C 只用直接求和。
- **建议**：W2 按实测速度选，倾向 B；S1 的对拍也在 W2。理由：B 对 WASM 友好。D-044 选"自写"时，NTT 推到延长期或第一阶段。
- **复审条件**：实测的鉴定成本远高于 §14.3 的粗估。论证见[附录](./spec/lenia-q16-draft.md#arg-d-023)。

### <a id="d-024"></a>D-024 参数的定点编码与合法格点
- 状态：提议 · 截止：W2 定编码草案；W3 实测后确认步长 · 拍板人：创始人（暂代后端/图形；到岗后可提修改）
- **问题**：参数怎样定点编码、格点多细。§8.4(5) 用"规则点相同"判同种，规范冻结后不能再改。
- **选项**：A 十进制定点（μ、σ 存为整数 × 10^−k）/ B 二进制定点（0.15 这类文献值不能精确表示）。
- **建议**：A。μ、σ 步长暂定 0.0001；β 用分母较小的有理数；R、T 为正整数，范围由 D-028 决定。理由：Chan（2019）发表的 μ、σ 最多到小数点后 3–4 位 [verify]，0.0001 能精确表示；更细的格点会让同一个种落在更多相邻格点上，评审量变大。
- **复审条件**：W1 核对论文参数的小数位数和 β 的分母 [verify]。有落不到格点的，在 v1.0 冻结前细化编码；不得把文献参数取整到最近的格点后登记为该文献种（D-040 第 1 条）；冻结后仍落不到的，标 `literature_unreproduced`。论证见[附录](./spec/lenia-q16-draft.md#arg-d-024)。

### <a id="d-025"></a>D-025 合法环面尺寸的取值、记录位置和选取规则
- 状态：提议 · 截止：W1 定测试用尺寸；合法尺寸集合和 D-028 的 R、T 范围一起，在 v1.0 冻结前定 · 拍板人：创始人（暂代后端/图形；到岗后可提修改）
- **问题**：GDD 已定环面属于规范、鉴定尺寸由规范固定、从几种合法尺寸中选取（§5.4、§20、D-041）。还没定有哪些尺寸、记在哪里、鉴定时怎么选。
- **选项**：A 只有一个尺寸（与"几种合法尺寸"不符）/ B 一组合法尺寸，模式标本记录自己的尺寸。草稿 v0.1 的选项 C"尺寸只属于鉴定协议"与 D-012、§5.4、§20 冲突，已删去。
- **建议**：B。取 2 的幂，暂定 128、256、512；512 用于大 R，以及 256 尺寸标本的局域性和扩张复查。鉴定取能容纳成体加边距的最小合法尺寸。第 0 阶段测试向量用 256；大 R 的成体加边距放不下时才用 512（规范草案附录测试协议第 4 条）。理由：兼顾成本和大生物；扩张体在小环面上会绕回来撞上自己。
- **复审条件**：出现在最大合法尺寸里也放不下的稳定生物。论证见[附录](./spec/lenia-q16-draft.md#arg-d-025)。

### <a id="d-026"></a>D-026 状态与参数的规范序列化格式
- 状态：提议 · 截止：W1 · 拍板人：创始人（暂代后端/图形；到岗后可提修改）
- **问题**：哈希、内容寻址、分享链接和承诺都要求同一个状态、同一组参数在任何实现里得到相同的字节。
- **选项**：A 定长头加行优先、小端序的 16 位原始数据 / B 以压缩格式（如 16 位 PNG）为规范形式（结果依赖库，不能算哈希）/ C 通用格式（如 CBOR）的规范子集（容易出现两种合法编码）。
- **建议**：A 用于哈希和存档；传输时可以压缩，但哈希只对解压后的规范字节计算；参数序列化为定长整数元组。理由：简单，任何语言都能逐字节写对；W1 的哈希链要用。
- **复审条件**：多通道 Lenia 的规范需要新格式（随新规范发，不改旧格式）。论证见[附录](./spec/lenia-q16-draft.md#arg-d-026)。

### <a id="d-027"></a>D-027 规范正文与参考实现冲突时以谁为准；出 bug 后已签发证书怎么处理
- 状态：提议 · 截止：W2 定原则，写进规范草案；第一条登记之前定证书处理细则 · 拍板人：创始人/制作人（涉及永久性承诺）
- **问题**：§5.4 说宇宙不打补丁，§14.2(6) 说实现永久归档，但没写两者不一致时以谁为准，也没写鉴定 bug 之后已签发的证书怎么办。
- **选项**：A 正文为准，已登记条目重新鉴定，活不下来的撤回（违背"永久成立"）/ B 已归档实现为准，给正文发勘误（规范留下"怪癖"）/ C 分阶段处理。
- **建议**：C。（1）规范＝正文加随规范发布的测试向量。（2）冻结前，发现冲突就改错的一方。（3）冻结后的宇宙语义冲突：已归档实现的行为确定且跨平台一致，就以它为准，给正文发勘误，不理想的在新版本规范里改；行为本身不确定的不定义任何宇宙，受影响的条目按正文重新鉴定。（4）鉴定测量的 bug 不改变宇宙：修好鉴定套件，重新签发受影响的证书，旧证书标"已更正"；不再满足登记条件的走 §15 的撤回流程，编号保留，状态改为 `withdrawn`。理由：既保住永久性，也留出修正的途径。
- **复审条件**：第一次真正发生冲突之后复盘。

### <a id="d-028"></a>D-028 16 位精度与 v1.0 允许的 R、T 范围
- 状态：提议 · 截止：W3 末后端提出建议，W4 评审会拍板；最晚在宇宙规范 v1.0 冻结前 · 拍板人：后端提议（到岗前创始人暂代），创始人在 W4 评审会拍板
- **问题**：16 位状态和总和为 2^16 的核权重够不够用。R 越大，每格分到的权重越小（粗算 R = 13 时最大单格权重约 300，R = 50 时约 20，近一半格子小于 5），所以精度和允许的 R、T 范围是同一个问题（§14.2、计划 §7）。早期警示：规范草案起草时用整数原型草算（未复核），R = 50 的单环核量化后 L1 误差约 2.4%，超过计划 §7.4 的 1% 线（暂定）。
- **选项**：A 保持 16 位状态、2^16 核权重、u32 累加 / B 提高核权重精度，双 u32 模拟 64 位累加（附录 A 和 WGSL 精确路径要改，变慢）/ C 保持 A，在 v1.0 里限制 R、T 范围。
- **判据**：本条同时决定 v1.0 允许的 R、T 范围，要（1）覆盖全部基准物种（D-045）；（2）覆盖准备导入的 Chan（2019）物种的 R、T [verify：W1 从论文发表的参数中查出最大值]；（3）覆盖 §8.3 离散化复跑要用的 R、T，暂定 R 为原值的 0.5–3 倍、T 为 0.5–4 倍（§14.5 的示例是 R 10–30、T 5–40）；（4）与 D-025 的合法尺寸相容。
- **建议**：按计划 §7.4 的判定规则（暂定）实测诊断。A 在判据范围内够用就选 A；不够时比较 B 和 C。选 C 时写明哪些文献物种和哪些离散化复跑因此做不了。结论和数据一起写进本条。
- **复审条件**：研究者或悬赏需要更大的 R、T。

- **影响**：选"自写"时，D-023 不在第 0 阶段；命名法规 v0 推到延长期（计划 §2.2），但 D-015 仍最晚在 W2 末、D-017 仍在 W3 拍板，不随命名法规顺延；拍板之前简介照旧写 "proposed"。选"推迟"时，D-021–D-026、D-028、D-033、D-034、D-037、D-045 的截止顺延到延长期。
- **复审条件**：工程师到岗时。

### <a id="d-045"></a>D-045 基准物种名单
- 状态：提议 · 截止：W1 末 · 拍板人：创始人/制作人（创始人暂代后端提出名单）
- **问题**：G2 要在约 10 个经典物种上比较整数版和 float64 版（§19.1、计划 §5）。名单决定 G2 有多大说服力，也决定内部测试用到 Chan 的哪些工作。
- **建议**：约 10 个，按计划 §5.1 的覆盖标准选。（1）只选 2019 论文里发表了完整参数（R、T、β、μ、σ、核函数族和生长函数族）的物种 [verify：W1 核对论文]，注明参数出自论文哪一处，不用仓库数据文件（D-040 第 6 条）。（2）至少 6 个柏拉图型，即 Davis（2024）没有归为非柏拉图型的物种，含 Orbium（暂定）。理由：G2 只对这些物种有约束力，柏拉图型太少，G2 就证明不了什么。（3）大 R 测试可以把 Orbium 放大到 R 约 40–50（暂定）。D-044 选"自写"时，第 0 阶段只跑 Orbium 加 3–4 个。名单和参数出处放在私有位置 [存档位置]；Chan 书面同意之前，规范草案附录只写汇总（计划 §5.3）。
- **复审条件**：某个物种培养不出初始形态时，按同一标准换；Chan 反对内部使用时，改用自己在随机汤里找到的结构（计划 §5.3）。

### <a id="d-046"></a>D-046 第 0 阶段计划对 GDD 继续标准的解释
- 状态：提议 · 截止：W1（创始人审阅计划时）· 拍板人：创始人/制作人
- **问题**：GDD §19.1 的继续标准有几处要先变成可以检验的标准。第 0 阶段计划 v0.1 §1.3 给了解释，v0.2 移到本条。W4 评审按它判定。
- **待确认的解释**：（1）"3 种平台逐位一致"＝3 个原生平台加 3 个桌面浏览器里的 WASM，共 6 个配置（已写进 GDD §19.1，D-041）；（2）"稳定复现约 10 个经典物种"＝确定性（G1）加行为一致（G2），非柏拉图型允许行为不一致，但必须记录；（3）"确认文献物种的导入许可"＝收到书面答复，或 W4 末按退路处理（G5、D-042）；（4）"提交伦理审查申请"＝已提交，或选定退路（S4、D-036）；（5）"创始人自己玩一周"＝≥ 5 次有日志的试玩（G8）；（6）"16 位精度够不够用"＝按计划 §7 的判定规则回答（D-028）；（7）"≥ 2 位研究者同意担任顾问"＝书面确认（邮件即可），并确认 D-040 第 7 条的条件（G3）；顾问须是人工生命或相关方向（元胞自动机、开放式 AI）的研究者（GDD §19.2，暂定）；（8）G4 的"场"＝与一位研究者的实时通话并有纪要；书面回答不计；一次通话有多位研究者时按人数计（访谈计划 §3）。
- **建议**：全部确认。理由：标准事先定死，评审会上不临时放宽（计划 §9.1）。
- **复审条件**：要改任何一条，先改计划，并在本条写明原因，不在评审会上改。

### <a id="d-047"></a>D-047 宇宙规范正文与测试向量的许可
- 状态：提议 · 截止：规范第一次公开之前（最晚 v1.0 冻结、第一条登记之前）· 拍板人：创始人/制作人
- **问题**：规范正文既不是图鉴数据（D-018），也不是代码（D-032）。别人要能照着规范自由地重新实现，测试向量也要能自由使用。
- **选项**：A 规范正文 CC BY 4.0，测试向量 CC0 / B 两者都用 CC0 / C 规范随代码用 MIT 与 Apache-2.0 双许可。
- **建议**：A（暂定）。理由：正文是文字，署名要求合理，与描述文字一致；测试向量是数据，跟随 D-018 的方向。涉及 Chan 物种的测试向量获准之前不公开（计划 §5.3），获准后按 D-018 的选项标许可。

### <a id="d-048"></a>D-048 永久图鉴与删除权
- 状态：提议 · 截止：第一阶段开放注册之前（与隐私政策、用户协议同时）· 拍板人：创始人/制作人（参考法律意见）
- **问题**：GDD §8.5(6) 规定条目只合并不删除；出处里有采集者和描述者的显示名，学名后有命名者署名（§8.5(9)），进了快照就收不回。玩家可能依法要求删除个人数据，被命名的在世者也可能撤回同意（§8.5(8)）。
- **选项**：A 出处只存显示名，与账户分开；收到删除请求后，之后的快照改为"匿名贡献者"，学名署名保留 / B 学名署名也改为匿名 / C 删除请求一律不影响已发布内容。
- **建议**：先按 A 起草隐私政策；学名署名能否保留、以在世者命名撤回同意后怎么办，交法律备忘 Q24；注册前在用户协议里如实告知。理由：学名署名是命名法规的核心，改动要有法律依据。
- **复审条件**：收到法律意见。
