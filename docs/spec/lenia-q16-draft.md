## 1. 范围与规范性

**本规范定义一个宇宙家族**：单通道、单核的经典 Lenia（GDD §5.3），状态为 16 位整数。给定规范标识、规则参数、环面尺寸和初始状态，本规范唯一地确定此后每一步的状态，以及核、查找表、状态和轨迹的哈希。

**不在本规范内**：鉴定测量（存活、局域性、速度等，见鉴定规格 assay v1 和 D-034）；查重；承诺的构造（命名法规 v0 和数据模型，D-001）；浮点预览；初始状态怎么得到（采集交接规格）；多通道 Lenia 和 Flow-Lenia（另发规范，D-026 复审条件）。

**用词**：

| 词 | 含义 |
|---|---|
| **必须** / **不得** | 一致性要求。违反任何一条，就不符合本规范 |
| **应当** | 推荐做法。不照做要有理由，但不影响一致性 |
| **可以** | 允许的做法 |
| "说明" | 解释和草算，不属于规范 |

**规范标识**：本草案是 `lenia-q16/0.1-draft`。它写在每一条序列化记录里（§8），所以不同版本算出的哈希一定不同。

## 2. 记号与整数类型

**整数类型**：

| 类型 | 范围 | 用在哪里 |
|---|---|---|
| u16 | 0 到 65535 | 状态 A、势 U |
| u32 | 0 到 2^32 − 1 | 核权重 w；每格的加权累加和 |
| i32 | −2^31 到 2^31 − 1 | 查找表的值；更新时的中间值 |
| i64、u64 | 64 位 | 核与查找表的生成 |

- 下文的算式都按**数学整数**理解。每处都给出上界，实现选的类型必须容纳得下。生成阶段的全部中间值都小于 2^63，可以全部用 i64 实现。
- 数值不得用宽度随平台变化的类型存放（如 Rust 的 usize）。
- 精确路径里**不得**有任何浮点运算，包括核与查找表的生成（D-022）。

**取整与辅助运算**（a、b、n 是整数，b > 0）：

| 记号 | 定义 |
|---|---|
| ⌊a / b⌋ | 向下取整：最大的整数 q，使 q·b ≤ a。负数也向负无穷取整。C 和 Rust 的 `/` 对负数向零取整，与此不同；Rust 可用 `div_euclid` |
| a mod b | a − b·⌊a / b⌋，取值 0 到 b − 1 |
| a >> k | 只用于 a ≥ 0，等于 ⌊a / 2^k⌋ |
| rne(a, b) | **四舍六入五成双**：q = ⌊a / b⌋，r = a mod b。2r < b 取 q；2r > b 取 q + 1；2r = b 时取 q、q + 1 中的偶数。对负数同样适用：rne(−3, 2) = −2，rne(−5, 2) = −2，rne(5, 2) = 2，rne(7, 2) = 4 |
| isqrt(n) | n ≥ 0 时，最大的整数 k，使 k² ≤ n。算法不限，但结果必须等于定义；不得只用浮点开方而不校正 |
| clamp(x, lo, hi) | **饱和截断**：x < lo 取 lo，x > hi 取 hi，否则取 x |
| gcd、lcm | 最大公约数、最小公倍数 |

**常数**：W = 2^16（核权重总和）；S = 2^16（半径的定点单位）；ONE = 2^30（定点 exp 的单位）。

## 3. 规则参数与定点编码

一个**规则点**由下面 7 个字段确定【提议，待 D-024】：

| 字段 | 编码 | 含义 | 合法范围 |
|---|---|---|---|
| 核函数族 kf | u16 枚举 | 1 = `exp-shell`（§5）；其他值保留 | 只有 1 |
| 生长函数族 gf | u16 枚举 | 1 = `gaussian`（§6）；其他值保留 | 只有 1 |
| R | u16 | 核半径，单位是格 | 5–50【提议，待 D-028】 |
| T | u16 | 每个时间单位的步数，Δt = 1/T | 5–40【提议，待 D-028】 |
| μ_q | u16 | μ = μ_q / 10000 | 1–9999【提议，待 D-024】 |
| σ_q | u16 | σ = σ_q / 10000 | 1–9999【提议，待 D-024】 |
| β | B 个分数 p_i / q_i | 第 i 圈的峰高，i = 0 到 B − 1，由内向外 | 见下【提议，待 D-024】 |

- **步长**：μ、σ 的格点步长 0.0001【提议，待 D-024；W3 实测后确认】。例：Orbium 的 μ = 0.15 编为 μ_q = 1500；σ ≈ 0.015 编为 σ_q = 150（有的来源写 0.014，即 140，以论文为准 [verify]）。
- **β 的规范形式**：1 ≤ B ≤ 4；每项 0 ≤ p_i ≤ q_i，1 ≤ q_i ≤ 12，gcd(p_i, q_i) = 1（0 写作 0/1，1 写作 1/1）；**至少一项等于 1/1**。B 的上限 4 和分母上限 12 都是暂定，W1 核对 Chan（2019）发表的 β 之后定 [verify]。
- **为什么要求最大项为 1**：核要归一化，β 整体乘一个正数，连续核和 §5 的整数核都不变（§5.4 只看各格的比例）。规定最大项为 1，同一个核就只有一种写法。文献里最大项不是 1 的 β，先除以最大项再编码 [verify：是否存在这种情况]。
- **只定义两个函数族**：核函数族只有 `exp-shell`（α = 4，不另设参数），生长函数族只有 `gaussian`。多项式型等其他函数族的公式没有核实，本版不定义，枚举值保留，不得使用。
- **规范不取整参数**：落不到格点上的值不是合法参数。文献参数落不到格点时，按 D-024 的复审条件处理：冻结前细化编码；不得把文献参数取整到最近的格点后登记为该文献种（D-040 第 1 条）。

**同一规则点**：规范标识相同，并且 §8.2 的参数记录逐字节相同。等价的说法：上表所有字段的整数值都相同，β 按规范形式逐项相同。GDD §8.4(5) 的"规则点相同"按此判定。环面尺寸 N 不属于规则点（§4）。

**参数记录的合法性**：实现必须检查下面各条，任何一条不满足就拒绝运行，不得自行修正：各字段在合法范围内；β 是规范形式；未用的 β 槽和保留字段为 0（§8.2）；§5.4 的总和 H > 0。

## 4. 世界

- **环面**：N×N 的格子，上下、左右相接。N 必须是合法尺寸之一：128、256、512【提议，待 D-025；第 0 阶段测试默认 256】。还必须满足 N ≥ 2R + 1，使核的每个偏移落在不同的格子上。不满足时世界不合法，实现必须拒绝运行。
- **坐标**：格子 (x, y)，x 是列，y 是行，0 ≤ x, y < N。格子 (x, y) 偏移 (dx, dy) 之后是 ((x + dx) mod N, (y + dy) mod N)，mod 按 §2 取非负值。
- **存储顺序**：行优先，下标 y·N + x。§8.4 的序列化按同一顺序。
- **状态**：每格一个 u16，值 a 表示 a / 65535。
- **N 记在哪里**：N 属于模式标本，不属于规则点。成体快照的尺寸就是环面尺寸，GDD §14.5 的 `window` 写 [N, N]（D-025）。鉴定时选哪个尺寸，由鉴定规格 assay v1 规定。同一个生物放在不同 N 的环面上，是不同的初始状态，轨迹哈希也不同。

**为什么除以 65535，不除以 65536**：

1. 1.0 能精确表示。满格是 65535，连续规则的 clip(·, 0, 1) 正好对应 clamp(·, 0, 65535)。除以 65536 时最大值是 65535/65536，表示不了 1。
2. 核权重总和恰好是 2^16（§5.4），所以 (Σ w·A) / 2^16 是 A 的加权平均，单位不变：势 U 和状态 A 都以 1/65535 为单位，u = U / 65535。这正是 GDD 附录 A 的 U = (Σ w·A) >> 16，不用另做换算。
3. 与测量报告的 float64 对照一致（"float64 版把整数状态除以 65535"）。

代价：1/65535 不是 2 的幂，生成查找表时要做一次除法（§6）。除法只在生成阶段出现，不影响每一步的运算。

## 5. 核的生成

**输入**：R、β（B 项）。**输出**：(2R + 1)² 个 u32 权重 w(dx, dy)，−R ≤ dx, dy ≤ R，全部非负，总和恰好 2^16。核只取决于核函数族、R 和 β，与 μ、σ、T 无关。

说明，连续定义（Chan 2019；GDD 附录 A）：r = |d| / R；壳 K_S(r) = β_⌊B·r⌋ · K_C(B·r mod 1)；核心 K_C(s) = exp(α − α/(4s(1 − s)))，0 < s < 1，α = 4 时即 exp(4 − 1/(s(1 − s)))；核在 r < 1 的格子上归一化到总和 1。

### 5.1 定义域

偏移 (dx, dy) 属于核的**定义域**，当且仅当 d² = dx² + dy² < R²（**严格小于**）。定义域外的权重为 0。

为什么用 < 不用 ≤：（1）与连续定义一致，归一化只在 r < 1 的格子上进行；（2）r = 1 时 B·r = B，圈号超出 β 的下标；（3）r = 1 时圈内位置 s = 0，核心本来就是 0，用 ≤ 也只多出权重为 0 的格子。

### 5.2 半径的定点表示

对定义域内的每个偏移：

```
ρ = isqrt(⌊d² · B² · S² / R²⌋)     # ρ = ⌊S · B · |d| / R⌋，没有取整误差
i = ρ >> 16                         # 圈号 = ⌊B · r⌋，0 ≤ i ≤ B − 1
f = ρ mod S                         # 圈内位置 s 的定点值：s ≈ f / S，向下取整到 1/S
```

- 对非负实数 x，isqrt(⌊x⌋) = ⌊√x⌋，所以 ρ 恰好是 ⌊S·B·|d| / R⌋，圈号 i 也是精确的。
- 上界：d²·B²·S² < 50² × 4² × 2^32 < 2^48。

### 5.3 核心函数

【提议，待 D-022；常数和误差分析 W3 定】

```
若 f = 0：  k = 0
否则：      y = rne(2^62, f · (S − f)) − 2^32    # y ≈ (1/(s(1−s)) − 4) · ONE ≥ 0
            k = expneg(y)                         # §5.5；k ≈ K_C(s) · ONE，0 ≤ k ≤ ONE
```

- f·(S − f) ≤ 2^30，所以 y ≥ 0；s = 1/2 时 y = 0，k = ONE。
- **两端的截断**：s → 0 或 s → 1 时 1/(s(1 − s)) 趋于无穷。f = 0 时直接取 0，不做除法；其余由 expneg 的截断处理：y ≥ 22·ONE 时 k = 0，约相当于 s < 0.040 或 s > 0.960。

### 5.4 权重量化：最大余数法

```
L   = lcm(q_0, ..., q_{B−1})          # ≤ 27720
h_j = k_j · p_i · (L / q_i)           # i 是格子 j 的圈号；h_j < 2^45
H   = Σ h_j                           # 对定义域内全部格子；H < 2^58
a_j = ⌊W · h_j / H⌋
r_j = W · h_j − a_j · H               # 余数，0 ≤ r_j < H
D   = W − Σ a_j                       # 0 ≤ D ≤ 余数为正的格子数
```

- **格子编号**按行优先：j = (dy + R)·(2R + 1) + (dx + R)；dy 从 −R 到 R 在外层，dx 从 −R 到 R 在内层。
- 把余数 r_j > 0 的格子按"r_j 从大到小，r_j 相同时 j 从小到大"排序，前 D 个格子的 a_j 各加 1，得到 w_j；其余 w_j = a_j。余数都对同一个 H 取，比较是精确的。
- 结果：w_j ≥ 0，Σ w_j = 2^16 恰好。单个权重最大可达 2^16（只有一个格子非零时），所以用 u32 存。
- H = 0 时规则点不合法（§3）。
- β 整体乘一个正数时，各 h_j 按同一比例变化，a_j 和余数的排序都不变，结果相同。所以 §3 规定最大项为 1，不会丢掉任何一种核。

**溢出上界**：Σ w_j = 2^16，状态最大 65535，所以每格 Σ w·A ≤ 2^16 × 65535 = 2^32 − 2^16 < 2^32，u32 累加不会溢出。改用 D-028 的方案 B 时要重新证明。

说明，草算（2026-10-21，用本节算法的 Python 原型脚本，未经复核）：单环核 R = 13 时最大权重 321，R = 50 时 22；R = 50 时，理想权重为正的格子约 46% 量化后小于 5，其中约 30% 取整成 0。与 D-028 的粗算一致。

### 5.5 定点 exp：expneg

【提议，待 D-022；常数和误差分析 W3 定】

输入 y ≥ 0，表示 t = y / ONE。输出约等于 e^(−t)·ONE，取值 0 到 ONE。只用整数运算，中间值小于 2^61。

```
series(g):                         # 0 ≤ g ≤ ONE；≈ e^(−g/ONE) · ONE
    acc = ONE;  term = ONE
    for m = 1, 2, ..., 16:
        term = rne(term · g, m · ONE)
        m 为奇数：acc = acc − term；m 为偶数：acc = acc + term
    return acc

E1      = series(ONE)                              # ≈ e^(−1) · ONE
ENEG[0] = ONE
ENEG[n] = rne(ENEG[n − 1] · E1, ONE)，n = 1..21    # ≈ e^(−n) · ONE

expneg(y):
    若 y ≥ 22 · ONE：return 0
    n = y >> 30                     # 整数部分，0..21
    g = y − n · ONE                 # 小数部分，0 ≤ g < ONE
    return rne(series(g) · ENEG[n], ONE)
```

- **区间约简**：e^(−t) = e^(−n)·e^(−g)。e^(−g) 用 16 项泰勒级数，每一项按 rne 取整；循环固定 16 次，term 变成 0 后可以提前结束，结果相同。
- e^(−n) 由 E1 连乘得到，不用抄写常数。实现可以预先算好存成表，但表值必须等于上面过程的结果。下表是过程的结果，供核对，与过程不一致时以过程为准：

| n | ENEG[n] | n | ENEG[n] | n | ENEG[n] |
|---|---|---|---|---|---|
| 0 | 1073741824 | 8 | 360200 | 16 | 121 |
| 1 | 395007541 | 9 | 132510 | 17 | 45 |
| 2 | 145315153 | 10 | 48748 | 18 | 17 |
| 3 | 53458457 | 11 | 17933 | 19 | 6 |
| 4 | 19666267 | 12 | 6597 | 20 | 2 |
| 5 | 7234815 | 13 | 2427 | 21 | 1 |
| 6 | 2661540 | 14 | 893 | | |
| 7 | 979126 | 15 | 329 | | |

- 核对值：expneg(0) = 1073741824；expneg(2^29) = 651257338；expneg(ONE) = 395007541；expneg(22·ONE − 1) = 0。
- 说明，草算（同上脚本）：随机抽 20 万个输入，与高精度参考值相比，绝对误差最大约 3·2^(−30)。高精度参考值只用来检验误差，不进入规范语义（D-022）。

## 6. 生长查找表

**输入**：μ_q、σ_q、T。**输出**：65536 个 i32，LUT[0..65535]。查找表只取决于生长函数族、μ、σ、T，与核无关。

说明，连续定义：u = U / 65535；G(u) = 2·exp(−(u − μ)²/(2σ²)) − 1；每步增量 Δt·G(u) = G(u)/T，以 1/65535 为单位是 65535·G(u)/T。

【提议，待 D-022；常数和误差分析 W3 定】对每个 U = 0..65535：

```
δ   = 10000 · U − 65535 · μ_q        # (u − μ)/σ = δ / den，精确；|δ| < 2^30
den = 65535 · σ_q                     # den < 2^30
若 |δ| ≥ 7 · den：
    e = 0
否则：
    v = rne(|δ| · 2^28, den)          # v ≈ |u − μ|/σ · 2^28
    y = rne(v · v, 2^27)              # y ≈ (u − μ)²/(2σ²) · ONE
    e = expneg(y)                     # §5.5
g = 2 · e − ONE                       # ≈ G(u) · ONE，−ONE ≤ g ≤ ONE
LUT[U] = rne(65535 · g, T · ONE)      # ≈ 65535 · G(u) / T
```

- **7σ 的判断**：|u − μ| ≥ 7σ 时 (u − μ)²/(2σ²) ≥ 24.5，超过 expneg 的截断（22），结果本来就是 0。先判断只是为了让 v·v 不超过 2^62。
- 上界：|δ|·2^28 < 2^58；v ≤ 7·2^28，v·v < 2^62；65535·g 的绝对值 < 2^46。
- **值域**：LUT[U] 随 g 单调，所以 −rne(65535, T) ≤ LUT[U] ≤ rne(65535, T)。T 在 5–40 时绝对值不超过 13107。本规范用 i32 存放和序列化（§8.3），T 的范围以后放宽也不用改格式。
- 远离 μ 的表项都等于 −rne(65535, T)，即每步衰减约 1/T。
- 说明，草算（同上脚本）：在 7 组参数上抽查（每隔 7 个 U 取一项），表项与 float64 算出的 65535·G(u)/T 之差都不超过 0.5。

<a id="sec-7"></a>
## 7. 一步更新

### 7.1 定义

设 A 是第 t 步的状态，t = 0 是初始状态。对每个格子 (x, y)：

```
U(x, y)  = ⌊ Σ w(dx, dy) · A((x + dx) mod N, (y + dy) mod N) / 2^16 ⌋
         = (Σ ...) >> 16                               # 0 ≤ U ≤ 65535
A'(x, y) = clamp(A(x, y) + LUT[U(x, y)], 0, 65535)
```

- 求和对全部 (2R + 1)² 个偏移进行，权重为 0 的项可以跳过。
- **同步更新**：所有格子的 U 都由第 t 步的 A 算出，再一起写成第 t + 1 步。不得边算边覆盖。
- **方向**：求和用 A(x + dx, y + dy)，即"相关"的写法。连续核中心对称，相关和卷积没有区别；但最大余数法按行优先打破平局，量化核可能不严格对称（§10），所以方向必须照写。用 NTT 之类按卷积计算的算法时，核要先翻转：w′(dx, dy) = w(−dx, −dy)。
- **中间值**：Σ w·A < 2^32（§5.4），用 u32；A + LUT[U] 在 −13107 到 78642 之间，用 i32。
- 一个**时间单位**是 T 步。"跑 2000 个时间单位"就是跑 2000·T 步。
- 除了规范标识、参数、N 和初始状态，没有别的输入影响结果：没有随机数，没有时钟，没有平台常数。

### 7.2 两种合法的卷积算法

规范只定义上面的精确整数和。任何算法，只要对每个格子算出同一个 U，都符合本规范；下面两种必须给出逐位相同的 U。

1. **直接求和**：按定义逐项乘加。WebGPU 上的精确路径（WGSL，第一阶段）只用这一种，u32 累加即可（GDD §14.2(2)）。
2. **数论变换（NTT）**：在模 M 的整数环上做 N×N 循环卷积（核先翻转，§7.1）。真实的和在 0 到 2^32 − 2^16 之间，只要 M > 2^32 − 2^16，模 M 的结果就等于真实的和。参考实现倾向用 998244353 = 119·2^23 + 1 和 754974721 = 45·2^24 + 1 两个素数，用中国剩余定理还原，只用 64 位运算【提议，待 D-023】。合法的 N 都是 2 的幂（§4），变换长度不用另做处理。

- 模数和两种算法的切换阈值属于参考实现的选择，不属于规范语义，写进参考实现的文档（D-023）。
- 求和顺序、线程数和 SIMD 宽度不影响结果：整数加法在不溢出时与顺序无关。

### 7.3 实现约束

附录"逐位一致的前提"的七条，在此成为规范要求（编号同附录）：

1. 精确路径里不得有浮点运算，包括核与查找表的生成（§5、§6）。W1–W2 在一台机器上生成核与查找表、作为文件分发，是临时的测试做法，只算"部分符合"（§9.1）。
2. WASM 构建不得使用 relaxed SIMD；普通 SIMD 可以用【提议，待 D-037】。
3. 数值用 §2 的定宽整数，不用宽度随平台变化的类型。
4. 不溢出的依据见 §5.4、§5.5、§6。测试构建应当打开整数溢出检查。
5. 每一处取整都按 §2 的定义，方向写在算法里。
6. 序列化按 §8。
7. 结果不得依赖哈希表的遍历顺序或线程调度。

## 8. 序列化与哈希

【提议，待 D-026（记录布局）、D-021（哈希算法）、D-033（哈希间隔）】

### 8.1 通用约定

- 多字节整数一律**小端序**。
- 每条记录以 8 字节 ASCII 的**格式标识**开头，接着是 32 字节的**规范标识**：ASCII，不足 32 字节的部分补 0x00。本版写 `lenia-q16/0.1-draft`。
- **哈希**：SHA-256（FIPS 180-4），对整条记录的字节计算。写成字符串时为 `sha256:` 加 64 个小写十六进制字符【提议，待 D-021】。
- 传输和分享链接里可以压缩，但哈希只对解压后的规范字节计算（D-026）。

### 8.2 参数记录（72 字节）

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 8 | 格式标识 `LQ16PARM` |
| 8 | 32 | 规范标识 |
| 40 | 2 × 8 | 8 个 u16，依次为 kf、gf、R、T、μ_q、σ_q、B、保留（必须为 0） |
| 56 | 4 × 4 | β 的 4 个槽，每槽 p（u16）、q（u16）。第 B 槽之后的槽 p = q = 0 |

规则点的哈希就是参数记录的 SHA-256。

### 8.3 生成结果的记录

| 记录 | 格式标识 | 40 字节的头之后 | 总长（字节） |
|---|---|---|---|
| 核 | `LQ16KERN` | R（u32）；(2R + 1)² 个权重（u32），按 §5.4 的行优先顺序，定义域外写 0 | 44 + 4·(2R + 1)² |
| 生长查找表 | `LQ16GLUT` | LUT[0..65535]（i32） | 262184 |

GDD §14.5 的 `generated.kernel` 和 `generated.growth_lut` 就是这两条记录的哈希（D-002）。

### 8.4 状态记录

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 8 | 格式标识 `LQ16STAT` |
| 8 | 32 | 规范标识 |
| 40 | 4 | 宽 N（u32） |
| 44 | 4 | 高 N（u32），本版必须等于宽 |
| 48 | 2·N² | 状态，行优先（§4），每格一个 u16 |

256×256 的状态记录长 131120 字节。GDD §14.5 的 `type_specimen.state` 是成体快照的状态记录的哈希。同一个快照在不同规范版本下哈希不同，这是有意的。

### 8.5 轨迹哈希链

【提议，待 D-033】间隔 I = 256 步，按步数计，不按时间单位计。一次运行从第 0 步跑到第 L 步。

```
hP  = SHA-256(参数记录)    hK = SHA-256(核记录)    hG = SHA-256(查找表记录)
S_k = SHA-256(第 k 步的状态记录)

c   = SHA-256("LQ16CHN0" ‖ 规范标识 ‖ hP ‖ hK ‖ hG ‖ I (u32) ‖ S_0)
链点 k = 256, 512, ...（不超过 L）；L 不是 256 的倍数时，再加上 k = L。按 k 从小到大：
c   = SHA-256("LQ16LINK" ‖ c ‖ k (u64) ‖ S_k)
```

- ‖ 表示字节串连接。哈希值以 32 个原始字节参与连接，不用十六进制字符串。
- **包含第 0 步**：链头绑定初始状态、参数、核和查找表，只看链就知道它从哪里开始，代价只是多算一次哈希。
- **最后一段**：跑满的步数常常不是 256 的倍数（T = 10 时 2 万步），所以第 L 步总是链点。
- 证书写最后的 c（GDD §14.5 的 `trajectory_hashes.chain`）、I 和 L；全部 S_k 都要保存，出现分歧时才能定位到第一个不同的分段（附录测试协议第 5 条）。L 和分段列表放在哪个字段，由数据模型定。

## 9. 一致性

### 9.1 符合本规范的实现必须做到

1. 对同一条参数记录和同一个 N，作出同样的合法性判断（§3、§4）。
2. 生成逐字节相同的核记录和查找表记录（§5、§6）。
3. 对同一个初始状态，每一步的状态都逐位相同（§7）。
4. 输出逐字节相同的记录和哈希链（§8）。

没有容差，没有例外。核与查找表从文件读入、只做到第 3、4 条的实现，只算"部分符合"，不能用于鉴定。

### 9.2 测试向量

随规范发布的测试向量是规范的一部分（§1）。v0.1 只定结构，向量随参考实现原型产出。演化向量的组成见附录测试协议第 1 条。

| V1 取整与开方 | rne 的正负平局；isqrt 在完全平方数两侧 | §2 |

### 9.3 出现分歧时

1. 依次比较：参数记录 → 核记录 → 查找表记录 → S_0 → 第一个不同的 S_k。核或查找表不同，先查 §5、§6，不必看演化。
2. 在第一个不同的分段里逐步比对，找到第一个不同的格子，再查它的 U 和 LUT[U]。
3. 判定错在哪一方，按 §1 的冲突原则处理【提议，待 D-027】。冻结之前，改错的一方并换新的草案标识。
4. 修好之后，全部测试向量在全部配置上重跑，不只重跑出问题的配置（附录测试协议第 9 条）。
5. 常见原因：溢出、usize、序列化、浮点混进了生成算法（计划 §9.4）；还有负数除法向零取整（§2）、NTT 前没有翻转核（§7.1）。

## 附录：设计决定的论证（从决策日志移来，2026-10-20）

下面是决策日志草稿 v0.1 中 D-021–D-026、D-033、D-034 的背景、选项和论证，已按 2026-10-20 的审查修订。它们都还是**提议**，没有拍板。拍板之后，结论写进正文，论证留在这里。

<a id="arg-d-021"></a>
### D-021 哈希算法：SHA-256 还是 BLAKE3

**背景**：内容寻址的状态存储（§14.1）、采集和描述承诺（D-001）、轨迹指纹（§14.2(4)）、核与查找表的哈希（D-002）都需要一种哈希算法。它一旦写进测试向量和证书，就只能在新版本规范里更换。§14.5 的草案用的是 `sha256:` 前缀。

| 选项 | 好处 | 代价 |
|---|---|---|
| SHA-256 | 标准化（FIPS 180-4）；几乎所有语言都内置，浏览器的 WebCrypto 也内置；第三方最容易独立核对 | 比 BLAKE3 慢 |
| BLAKE3 | 很快，支持并行和树形哈希 | 浏览器没有内置，要另带库；不是 NIST 标准算法，几十年后的可得性略弱 |

**建议**：SHA-256。速度不是瓶颈：一张 256×256 的 16 位状态只有 128 KiB，而且每 256 步才算一次。长期可复核（§14.9 的"公司倒闭演练"）比速度重要。所有哈希字符串都带算法前缀（如 `sha256:`），将来的规范版本换算法也不会产生歧义。哈希的输入是规范序列化之后的字节（D-026）。

**影响**：本规范；数据模型与导出格式；命名法规 v0（承诺的构造）。

**复审条件**：SHA-256 出现可实际利用的碰撞攻击。届时在新版本规范里增加算法，旧条目不变。

<a id="arg-d-022"></a>
### D-022 确定性 exp 与定点数学方案

**背景**：核心函数 K_C(r) = exp(α − α/(4r(1−r))) 和生长函数 G(u) = 2exp(−(u−μ)²/(2σ²)) − 1 都要算 exp（GDD 附录 A）。D-002 规定核和查找表由规范算法生成，§5.4 规定只用整数和定点运算。各平台浮点 exp 的实现结果不同，不能直接用。

| 选项 | 好处 | 代价 |
|---|---|---|
| A 纯定点 exp：规范正文写出完整算法（区间约简加多项式或查表）和全部常数 | 第三方只看规范就能实现；符合 §5.4 | 要自己分析误差上界；工作量最大 |
| B 钉死某个版本的软件数学库 | 实现快 | 规范要引用外部代码，用别的语言的第三方很难逐位复现；库停止维护时有风险 |
| C 生成阶段允许用 float64 的基本运算自写 exp | IEEE 754 规定基本运算正确舍入，原则上可以跨平台一致 | 与 §5.4"只用整数和定点运算"不符，要改 GDD；第三方要防编译器优化改变运算 |

**建议**：A。W1 定方向（纯整数定点），因为第 0 阶段计划 §4.3(1) 要求精确路径里没有浮点，包括生成算法；W3 定常数和误差分析。另外用任意精度计算得到离线参考值，只用来检验定点结果的误差，不进入规范语义。常数定下来之前，W1–W2 的跨平台确定性测试可以先在一台机器上生成核和查找表，作为文件分发到其他平台，只比对演化本身。

**影响**：GDD 附录 A；本规范；参考实现原型。

**复审条件**：定点误差在某些参数区域（例如 σ 很小时）明显改变物种行为。

<a id="arg-d-023"></a>
### D-023 NTT 模数与直接求和的切换

**背景**：§14.2(1) 规定半径小时直接求和，半径大时用数论变换（NTT），两种算法的结果逐位相同。附录 A 的设计保证累加和小于 2^32（65535 × 2^16 < 2^32）。

**关键一点**：两种算法算的是同一个精确的整数卷积，切换点只影响速度，不影响结果。所以规范只需要定义"环面上的精确整数循环卷积"，NTT 模数和切换阈值属于参考实现的选择，不写进规范语义。

| 选项（模数） | 好处 | 代价 |
|---|---|---|
| A 一个大于 2^32 的 NTT 友好素数，例如 2^64 − 2^32 + 1 | 一次变换；支持很长的二次幂长度 | 乘法需要 128 位中间结果，WASM 里要软件模拟，较慢 |
| B 两个约 30 位的素数加中国剩余定理，例如 998244353 = 119·2^23 + 1 和 754974721 = 45·2^24 + 1，乘积约 7.5 × 10^17，大于 2^32 | 只用 64 位运算，对 WASM 友好 | 要做两次变换；实现稍复杂 |
| C 不用 NTT，只用直接求和 | 最简单 | 每格的乘加次数随 R² 增长，大半径时慢 |

**建议**：W2 按实测速度在 A、B 里选，倾向 B；S1 的对拍也在 W2（第 0 阶段计划 §3.2）。环面尺寸取 2 的幂（D-025），NTT 长度就不用另做处理。切换阈值按实测定，写进参考实现的文档，不写进规范。测试要求两种算法在所有测试向量上逐位相同。WebGPU 上的精确路径只做直接求和（§14.2(2)）。单人启动、创始人自己写最小版本时（D-044），NTT 推到延长期或第一阶段，第 0 阶段只用直接求和。

**影响**：GDD §14.2、§14.3；本规范（只写卷积语义）；参考实现原型。

**复审条件**：实测的鉴定成本远高于 §14.3 的粗估。

<a id="arg-d-024"></a>
### D-024 参数的定点编码与合法格点

**背景**：D-002 规定参数用定点编码，具体怎么编没定。§8.4(5) 用"规则点相同"判同种，而规则点按规范的参数格点判定。条目编码、查重、分享链接和测绘都依赖它，规范冻结后不能再改。文献参数多是十进制小数，例如 Orbium 的 μ = 0.15，σ 约为 0.015（有的来源写 0.014，以论文为准）。

| 选项 | 好处 | 代价 |
|---|---|---|
| A 十进制定点：μ、σ 存为整数 × 10^−k | 文献里的十进制参数能精确表示；界面输入直观 | 换算到内部定点运算时要规定取整 |
| B 二进制定点：μ、σ 存为整数 × 2^−k | 与内部运算对齐 | 0.15 这样的值不能精确表示，文献参数只能取近似 |

**建议**：A。

- μ、σ 的步长暂定 0.0001。理由：Chan（2019）发表的 μ、σ 最多到小数点后 3–4 位 [verify]，0.0001 能精确表示它们；更细的格点会让同一个种落在更多相邻格点上，评审量变大。
- β 用分母较小的有理数表示。Chan（2019）发表的 β 常写成分数 [verify]，分母上限在核对论文里的参数之后定。
- R、T 为正整数。v1.0 允许的 R、T 范围由 D-028 决定。
- 核函数族、生长函数族用规范里的枚举名。
- **同一规则点**＝规范版本相同，且所有编码后的整数完全相同。
- 控制台"微调"模式的最小步长等于格点步长。

步长的取舍：格点越细，同一个种出现在相邻格点上的情况越多。相邻格点上的同一个种不会被自动判同，只能靠连续性检验或评审，评审量会变大。格点越粗，越可能漏掉只在很窄的参数区间里存在的种。W3 用 Orbium 等物种实测，看相邻格点上的行为是否明显变化，再确认步长。

**影响**：GDD §5.4、§8.1、§8.4(5)、§14.5；本规范；数据模型；查重与评审规格 dedup v1。

**复审条件**：W1 核对 Chan（2019）发表的参数的小数位数和 β 的分母 [verify]。有落不到格点的，就在 v1.0 冻结之前细化编码，让文献参数能精确表示；不得把文献参数取整到最近的格点后登记为该文献种（D-040 第 1 条）。冻结后仍落不到格点的，标 `literature_unreproduced`。

<a id="arg-d-025"></a>
### D-025 合法环面尺寸的取值、记录位置和选取规则

**背景**：GDD 已经规定：规范包含网格与边界（环面，§5.4）；鉴定用的世界尺寸由规范固定（§20、D-012）；从规范规定的几种合法尺寸中选取（附录 D 补充、D-041）。还没定的是：具体有哪些尺寸；尺寸记在哪里；鉴定时怎么选。§14.3 写"128×128 到 256×256 的窗口"，§14.5 的模式标本有 `window` 字段。局域性、扩张体判定和繁殖率都和尺寸有关：扩张体或辐射体在小环面上会绕回来撞上自己。

| 选项 | 好处 | 代价 |
|---|---|---|
| A 规范规定一个固定尺寸，所有鉴定都在这个尺寸上跑 | 最简单；条目之间可比 | 大生物和扩张体放不下；小生物浪费算力；和附录 D"几种合法尺寸"不符 |
| B 规范规定一组合法尺寸，模式标本记录自己所在的尺寸，鉴定协议规定怎样选尺寸 | 兼顾成本和大生物 | 同一个种在不同尺寸上的轨迹哈希不同，要写清楚以哪个为准 |

草稿 v0.1 还有一个选项 C"尺寸只属于鉴定协议，规范不管"。它和 D-012、§5.4、§20 冲突，已删去。

**建议**：B。合法尺寸取 2 的幂（与 D-023 联动），暂定 128、256、512。512 用于大 R，以及对 256 尺寸标本的局域性和扩张复查。环面尺寸属于模式标本：成体快照的尺寸就是环面尺寸，§14.5 的 `window` 按此注明。鉴定协议规定取能容纳成体并留出边距（暂定）的最小合法尺寸；局域性和扩张的判定要在更大的合法尺寸上再跑一次，排除环面绕回造成的假象。最大合法尺寸上的标本没有更大的尺寸可以复查，证书如实写明（暂定）。具体集合和 D-028 的 R、T 范围一起，在 v1.0 冻结前定。第 0 阶段的测试向量用 256；大 R 的成体加边距放不下时才用 512（见下文测试协议第 4 条；W1 定）。

**影响**：GDD §5.4、§8.2、§8.3、§14.3、§14.5、§20；本规范；鉴定规格 assay v1；数据模型。

**复审条件**：出现在最大合法尺寸里也放不下的稳定生物。

<a id="arg-d-026"></a>
### D-026 状态与参数的规范序列化格式

**背景**：哈希（D-021）、内容寻址存储（§14.1）、分享链接（§14.4）和承诺（D-001）都要求同一个状态、同一组参数在任何实现里得到完全相同的字节。W1 就要输出 Orbium 的第一条哈希链，所以本条和 D-021 都在 W1 定。

| 选项 | 好处 | 代价 |
|---|---|---|
| A 定长头（格式标识、规范版本、宽、高）加行优先、小端序的 16 位原始数据 | 简单，任何语言都能写 | 体积大，传输时要另外压缩 |
| B 以压缩格式（16 位 PNG 等）作为规范形式 | 体积小 | 压缩结果依赖库和参数，同一个状态可能得到不同的字节，不能用来算哈希 |
| C 通用序列化格式（如 CBOR）的规范子集 | 容易扩展 | 规范化规则复杂，容易出现两种合法编码 |

**建议**：A 用于哈希和存档。传输和链接里可以压缩，但哈希永远对解压后的规范字节计算。参数也序列化为定长的整数元组，字段顺序写进规范。承诺的具体构造（对哪些字段取哈希、是否加随机数）在命名法规 v0 和数据模型里定，用本条的序列化。

**影响**：本规范；数据模型与导出格式；系统架构与接口契约。

**复审条件**：多通道 Lenia 的规范需要新格式。届时随新规范发新格式，不改旧格式。

**背景**：下面三个数会写进测试向量和证书格式，必须在规范冻结前定下来。GDD 给了数值，但还没有实测依据。

### D-034 鉴定测量是否逐位可复现；查重嵌入模型是否归档

**背景**：鉴定证书一经签发就永久保留（§8.3）；§14.9 的"公司倒闭演练"要求陌生人只拿公开快照就能逐条复核。鉴定里有些测量（拟合质心轨迹、频谱、自愈指数）自然会用浮点计算；查重用的是学到的嵌入，还参考基础模型的视觉嵌入（§8.4）。

| 选项（鉴定测量） | 好处 | 代价 |
|---|---|---|
| A 所有测量都逐位可复现（整数或定点） | 复核最简单 | 拟合、频谱这类计算写成定点很费工 |
| B 所有测量都用 float64，钉死实现版本，复核时允许误差 | 实现快 | 分类边界附近的复核结果可能不同 |
| C 分层：决定条目身份和状态的量逐位可复现；描述性的连续量用 float64 | 兼顾 | 要写清楚每个量属于哪一层 |

**选项（查重模型）**：归档模型权重和代码 / 只记录模型版本 / 不归档。

**建议**：

- 鉴定选 C。存活、局域性、轨迹哈希和用于自动判定的类别逐位可复现；速度、自愈指数等描述性的量用 float64，钉死实现版本，在证书里写明精度。自我修复测试要加噪声，噪声由规范化的确定性伪随机数生成器产生，种子写进证书。
- 查重：每次自动判定（`auto_new`、`auto_same`）都记录所用模型的版本，并随每月快照（§14.9）归档模型权重和代码。只有权重可以归档、可以再发布的模型才能用于自动判定；许可不允许再发布的外部基础模型，只作为评审时的辅助证据。嵌入不决定物种身份，评审的结论和证据都写进事件日志。

**影响**：GDD §8.3、§8.4、§14.9；鉴定规格 assay v1；查重与评审规格 dedup v1；数据模型。

**复审条件**：第一次"公司倒闭演练"不通过。

<a id="det-prereq"></a>
### 逐位一致的前提（原计划 §4.3，编号不变）

1. 精确路径里没有任何浮点运算，包括核权重和生长查找表的生成（D-022）。W1–W2 先在 P1 上生成核和查找表、作为文件分发到其他配置，是临时的测试做法，不属于规范语义；W3 换成规范的定点生成算法之后，测试全部重跑。
2. 不用 WASM 的 relaxed SIMD：这类指令允许不同实现给出不同结果。普通 SIMD 可以用（D-037）。
3. 数值一律用定宽整数（u16、u32、u64）。不用 usize 存数值：它在 wasm32 上是 32 位，在 64 位原生平台上是 64 位。
4. 按设计不会溢出：核权重总和为 2^16、状态最大为 65535 时，Σw·A ≤ 2^16 × 65535 < 2^32。改用 D-028 的方案 B 时要重新证明。
5. 取整规则写死：右移是向下取整；查找表生成里的每一处取整都写明方向。
6. 状态的规范序列化写死：行优先，小端字节序（D-026）。
7. 结果不依赖哈希表的遍历顺序或线程调度。整数加法在不溢出时和求和顺序无关，所以多线程和 SIMD 求和不影响结果；但规范仍然写明求和的定义。

<a id="det-protocol"></a>
### 测试协议（原计划 §4.2）

1. **测试向量** = 规范草案版本 + 规则参数 + 生成的核与查找表的哈希 + 初始状态的哈希 + 环面尺寸 + 步数。
2. **初始状态**：基准物种用整数版培养出的成体快照：用论文发表的参数，从随机汤或简单的种子出发运行，直到质量稳定，再截取（计划 §5.3）。另加 2 个随机汤，由固定种子的整数伪随机数生成。随机汤是混沌的，任何一位的差异都会很快放大，所以是最严格的逐位测试。
3. **步数**：每个测试向量跑满 2000 个时间单位（GDD §8.3，D-033），也就是 2000 × T 步：T = 10 时为 2 万步，T = 40 时为 8 万步。
4. **环面**：默认 256×256（暂定，D-025）。R 约 50 的 Orbium 放大版在 256² 上仍放得下，先用 256²；成体加边距放不下时，才用 512²。512² 主要用于 M1、M2 的速度测量。
   - **时间上限**：W1 末在 P1 上实测大 R 向量（以及 T = 40 的向量）单次运行的时间，推算浏览器里的时间。某个向量在单个浏览器上超过 1 小时（暂定）时，浏览器上的这个向量缩短为 200 个时间单位；P1–P3 仍跑满 2000 个时间单位。这一点写进计划的 G1。
   - **粗算**（暂定）：R = 50 时核约 7,850 格，256² 环面每步约 5 × 10^8 次乘加，跑满 2 万步约 10^13 次。浏览器里的 WASM 只做直接求和，而且不用线程（D-037），单线程按每秒 10^9–5 × 10^9 次算，每次约 0.6–3 小时，三个浏览器各跑一次；出现分歧后全部重跑，时间还要翻倍。512² 上是 4 倍。
5. **哈希链**：每 256 步（GDD §14.2(4)，D-033，暂定）对规范序列化后的状态取一次哈希（D-021），和上一个链值连起来。保存全部分段，不只保存链头，这样出现分歧时能定位到第一个不同的分段。
6. **构建**：所有配置用同一个代码提交。测试构建打开整数溢出检查，作为前提第 4 条溢出证明的回归检验；普通发布构建也要跑，两者的哈希链必须相同。
7. **通过**：6 个配置上，全部测试向量的全部分段逐位相同。没有容差，没有例外。W3 之后，核与查找表在每个配置上由规范算法各自生成，哈希也逐位相同。
8. **算法一致（S1）**：在 P1 上，直接求和版和 NTT 版对同一组测试向量给出相同的哈希链。
9. **出现分歧时**：找到第一个不同的分段，从那里逐步比对，直到找到原因。修好之后**全部**重跑，不只重跑出问题的配置。
10. **float64 对照**只在 P1 上跑。它不要求跨平台一致，只用来做行为对比（[测量报告](../phase0/measurements.md#tolerances)）。

### 精度诊断（原计划 §7.1–7.3）

决定本身是 D-028（精度与 v1.0 允许的 R、T 范围），判定规则（暂定）在计划 §7.4。

**问题在哪里**：GDD 附录 A 的草案是：状态 16 位；核权重非负、总和为 2^16；势 U = (Σw·A) >> 16，用一个 u32 累加。正因为不超过 32 位，WebGPU 上才能写逐位精确的直接求和版（GDD §14.2(2)）。精度可能在三处不够：

- **核权重**：总和固定为 2^16，平均每格约 2^16 / (πR²)。R = 13 时约 120，R = 50 时只有约 8。R 越大，量化的相对误差越大，核边缘的小权重会被取整成 0。
- **状态和增量**：状态的最小单位是 1/65535。T 越大，每步的增量 Δt·G 越小，小增量会被取整掉，接近平衡时的细微变化可能丢失。
- **生长查找表**：势的分辨率是 1/65536。σ = 0.015 时，生长函数的钟形（约 ±3σ）覆盖约 5900 个表项（估算）。估计够用，诊断时一并确认。

所以，"够不够用"的答案取决于 v1.0 允许的 R、T 范围，不是一个简单的是或否。正文 v0.1 先写一个候选范围：R 5–50，T 5–40（暂定）。

**怎么诊断**：

1. **核与查找表扫描**（W1，不用跑模拟）：R 从 5 到 60（暂定），计算量化核和理想核之间的 L1 误差、各环的质量误差、被取整成 0 的格子比例。T 从 5 到 40，计算查找表里最小的非零增量，以及被取整成 0 的表项比例。
2. **整数对 float64 的行为对比**（W2–W3）：见[测量报告](../phase0/measurements.md#tolerances)，包括大 R 测试和 T = 40 的 Orbium。
3. **分离误差来源**（只对没通过 G2 的柏拉图型物种做）：在 float64 框架里每次只量化一处，看哪一处能重现失败：只量化核权重；只把状态每步量化到 16 位；只把生长函数换成整数查找表。
4. **试跑方案 B**（W3，只在原生版上）：误差来自核权重时，提高核权重的精度，看失败是否消失，同时测速度损失。

**各方案的代价**（A、B、C 按 D-028 的定义；D 在 D-028 之外）：

| 方案 | 内容 | 代价 |
|---|---|---|
| A | 16 位状态，核权重总和 2^16，u32 累加；v1.0 的 R、T 范围满足 D-028 的四条判据 | 没有额外代价；WGSL 精确路径简单 |
| B | 16 位状态，核权重总和提高到 2^24 或 2^32（暂定），64 位累加。原生和 WASM 有 64 位整数；WGSL 没有，要用两个 u32 模拟，就是 GDD §14.2 说的"双 u32" | 前提第 4 条的移位和溢出证明要改；WGSL 精确路径变慢，慢多少要估算；原生和 WASM 也变慢，M1 要重测 |
| C | 保持 A，在 v1.0 里把 R、T 限制在比判据更窄、A 够用的范围内 | 离散化复跑（GDD §8.3）往更大的 R、T 扩展时受限，柏拉图型的判定可能受影响；部分文献物种可能做不了，要写明；以后放宽要发新版规范 |
| D | 诊断指向状态量化，A、B、C 都解决不了：改状态位数 | 相当于另一份规范（如 lenia-q24）。超出第 0 阶段的范围，提交评审会 |
